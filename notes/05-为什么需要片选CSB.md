# 为什么需要片选 CSB

> 问题的本质：**为什么 I²C 只要 2 根线，SPI 却非得多一根片选？**

## 一、直接回答：SPI 用"硬件片选"替代了 I²C 的"协议寻址"

| | **I²C** | **三线 SPI（LMX2541）** |
|---|---|---|
| 帧的开始 / 结束 | START / STOP **条件**（SDA 在 SCL 高时的跳变） | **CSB 的下降沿 / 上升沿** |
| 选哪个芯片 | 数据流里的 **7 位地址** | **CSB 拉低选中谁** |
| 谁来界定边界 | **协议自己**（编码在时序里） | **一根专用线** |

> **I²C 不是"不需要片选"，而是把片选和帧边界都编码进了数据流。**
> 代价是：必须用开漏 + 线与，速度上不去，而且是半双工时分复用。
>
> **SPI 反过来 —— 牺牲一根引脚，换来全双工、更高的时钟速率、以及不用管总线仲裁。**
> CSB 就是那个"用引脚换复杂度"的产物。

## 二、CSB 具体在干四件事

### 1. 界定帧的边界 —— 最根本的作用

LMX2541 的寄存器写入是**定长字**（据我所知是 32 位，含地址和数据）。芯片**内部没有位计数器来数"收够了没有"**，它靠 CSB 划界：

```
CSB 下降沿  →  复位内部移位寄存器，准备接收新的一帧
     ↓
SCK 打 N 个脉冲，SDI 依次送入
     ↓
CSB 上升沿  →  把移进来的数据锁存 → 生效
```

**如果没有 CSB**，芯片就必须靠"数够 N 个时钟沿"来判断一帧结束。这带来一个致命问题：

> **只要时钟线上多一个毛刺，后续所有数据全部错位。**

而且是**永久错位** —— 计数器已经乱了，后面每一帧都会写到错误的寄存器位。只能复位整个芯片才能恢复。

**有了 CSB，每帧开始时移位寄存器被无条件复位。** 一个毛刺最多毁掉这一帧，下一帧重新对齐。

> 这是从"**会死锁**"变成"**偶尔写错一次**"的差别。

### 2. 指示"什么时候执行"

注意上一条里的**锁存动作发生在 CSB 上升沿**，而不是第 N 个时钟沿。

这是有意的设计，意味着：

- **数据搬移**和**生效**是两个分离的动作
- 你可以在 SCK 停下来、数据已就位但**还没生效**的状态下安全等待
- 真正"按下回车"的是 **CSB 拉高那一刻**

对 PLL 这种**有状态、有顺序要求**的器件很重要：某些寄存器必须在 VCO 校准前写完，不能让它们零散地、提前地生效。**CSB 提供了一个明确的提交点（commit point）。**

### 3. 多芯片寻址

一条 SCK + 一条 SDI 可以**并联挂多颗芯片**，各自一根 CSB：

```
MCU ──┬── SCK ──┬──────┬──────
      │         │      │
      ├── SDI ──┼──────┼──────
      │         │      │
      ├── CSB1 ─┘      │        ← 只有被拉低的这颗会响应
      │                │
      └── CSB2 ────────┘
      │         │      │
   LMX2541#1  LMX2541#2  ...
```

> **SDI 上的数据所有芯片都收到了，但只有 CSB 被拉低的那颗会把它移进寄存器。**
> 其他芯片因为 CSB 为高，直接忽略时钟。

**如果用 I²C 实现同样的事**：两根线就够（靠地址区分），但速度慢十倍以上，而且多主机仲裁要额外处理。

**这就是典型的"引脚换速度"权衡：**
- I²C 省 2 根线，但慢
- SPI 多 N-1 根片选，但快

### 4. 上电和复位时的防误写 —— 最容易被忽略

**这一点在实际调试中非常要命：**

MCU 复位期间，GPIO 处于**高阻态（输入态）**。此时：

- SCK 可能因为外部干扰、上拉、或别的电路耦合而**随机跳变**
- SDI 电平不确定

**如果没有 CSB 屏蔽**，这些随机跳变会被芯片当成有效时钟，往里写进**随机数据**。后果可能是：

- 写进非法分频比 → VCO 校准失败
- 写进错误的输出功率设置 → 可能损坏后级
- 芯片进入未知状态，且**你不知道它被写了什么**

**有了 CSB 就简单了**：只要在 MCU 上给 CSB 加一个**上拉电阻**，芯片在 MCU 复位期间就一直处于"未选中"状态，SCK 上任何跳变都被忽略。

> **这是硬件设计上的标准做法 —— CSB 一般都要加上拉。**
> 很多 PLL 调试失败就栽在这里：软件看着没错，但芯片上电时已经被噪声写坏了。

## 三、一句话总结

> **CSB 不是"多余的一根线"，它是 SPI 协议里承担
> 「帧边界 + 寻址 + 提交时机 + 防误写」四项职责的关键信号。**
>
> I²C 把这些职责编码进了协议时序（START/STOP + 地址），所以只需要 2 根线；
> SPI 把它们交给一根专用硬件线，换来简单、快速、全双工。

## 四、调试 LMX2541 的实际建议

| # | 建议 | 理由 |
|---|---|---|
| 1 | **CSB 一定加上拉电阻**（典型 10kΩ） | 防上电误写的第一道防线 |
| 2 | **CSB 空闲保持高** | 确认初始化代码一上电就先把 CSB 置高 |
| 3 | **CSB 拉高后留一点时间**再发下一帧 | 写太快会导致相邻两帧被当成一帧 |
