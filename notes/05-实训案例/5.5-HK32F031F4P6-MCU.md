## 一、MCU 基础

### 1.1 MCU 的分类（课件 P.5）

| 分类维度 | 类型 |
|---|---|
| 按**处理的数据位数** | 4 位、8 位、16 位、32 位、64 位 |
| 按**指令结构** | **CISC**（Complex Instruction Set Computer，复杂指令集计算机）、**RISC**（Reduced Instruction Set Computer，精简指令集计算机） |
| 按**存储器架构** | **哈佛架构**、**冯诺依曼架构** |
| 按**用途** | 通用型微控制器、专用型微控制器 |

### 1.2 MCU 发展历程（课件 P.7）

> MCU 由 Intel 率先提出，经过 4 位、8 位、16 位、32 位乃至 64 位 MCU 迭代更新，已广泛应用于多种场景。目前市场上以 **8 位和 32 位 MCU 为主**，未来随着产品性能要求的不断提高，**32 位 MCU 的市场规模将进一步扩大**。而在国内，现阶段 8 位、32 位 MCU 企业居多，未来企业加大研发投入，将进一步实现 **MCU 的国产替代**。

### 1.3 HK32F031F4P6 概述（课件 P.8）

- 厂商：**深圳市航顺芯片技术有限公司**；
- 基于 **ARM Cortex-M0** 研发设计，形成 **HK32F030、HK32F031、HK32F03X** 三大系列，统称 **HK32F03x 产品线**；
- **HK32F031x 系列是低功耗 MCU 芯片**；
- 典型封装结构为 **TSSOP20，0.65 mm pitch**。

## 二、本案例的核心概念：测试模式（Test Mode）

### 2.1 为什么需要测试模式（课件 P.12）

> 一般在芯片设计开发时，由设计人员去设计芯片的**可测性**，以满足芯片后续在测试过程中提高**测试覆盖率**。然而从芯片的功能设计上考虑，**不可能专门为测试保留足够多的引脚**，芯片仅能从内部引出固定数量的引脚，导致**引脚资源有限**。为了仅通过芯片引出的引脚来完成内部所有模块的测试，就需要**设计测试模式以提高芯片测试覆盖率**。

**不同芯片进入测试模式的方法不同，主要有**：

```
(1) 使用测试机向芯片输入指定的 PassCode          ← 本案例用这种
(2) 某些芯片需要向指定引脚施加高/低电平
```

> **这是理解本案例所有测试项的钥匙**：HK32F031F4P6 的绝大多数测试项，都是"**先输入 PassCode 切进某个专门测试模式 → 再跑 Pattern 观察输出**"。这也是课件 P.19 专门用一页讲 `测试PassCode` 的原因。

### 2.2 功能测试的本质（课件 P.13）

> **功能测试本质上就是验证芯片内部一系列逻辑功能操作的正确性。** 一款芯片的设计是为了完成某些特定的功能，所以芯片测试具体某个功能时，必须向芯片输入一段**激励信号（Pattern）**，然后测试机接收到经芯片处理后的**输出响应**，并按照 Pattern 中预期输出去比较，**若实际输出与期望输出不匹配时，该项测试就失败了**。

### 2.3 DFT（可测试性设计）测试（课件 P.14）

| 技术 | 做法 |
|---|---|
| **SCAN 测试** | 把芯片中的**触发器都串联起来**，把数据从整个链路上位移过去，即可控制和观察电路中每个节点的输入输出状态，实现测试的目的 |
| **BIST 测试** | 本质是**测试机给芯片一个激励信号，触发芯片内部的电路运行内部的测试 Pattern** |

### 2.4 频率测试（课件 P.15）

> **频率测试为测量内部锁相环（PLL）以及其他一些其他震荡电路产生的频率是否符合预期。** PLL 是一种控制系统，它生成输出信号，该输出信号的**相位与输入信号的相位有关**。

> **工程实现**：HK32F031 案例用 **TMU**（时间测量单元）测频 —— `PA4` 复用为 **TMU0**、`PA7` 复用为 **TMU2**（见 DUT 板资源分配表）。

## 五、各测试项的实施细节

### 5.1 OS 开短路（P.20）

| 项 | 值 |
|---|---|
| 工作条件 | 设置待测引脚加流 **FI = ±100 µA**，然后测量电压 |
| 测试要求 | 对所有有上下保护二极管的芯片引脚做 OS 测试；**FI = +100 µA 时 Limit 为 VOUTmin = 0.2 V，VOUTmax = 1.2 V；FI = −100 µA 时 Limit 为 VOUTmin = −1.2 V，VOUTmax = −0.2 V** |

### 5.2 VOH/VOL（P.24）

> 按照 **VOHT 和 VOLT 测试模式**，**输入 PassCode 进入相应的测试模式**，检查输入的 Pattern 中期望输出高电平的引脚是否为高电平或者低电平。

> **注意**：与 CD4511 不同，MCU 的 VOH/VOL **不走 PMU 加压测流**，而是**在测试模式下跑 Pattern 比较电平** —— 因为 MCU 引脚功能复用复杂，必须切到测试模式才可控。

### 5.3 VOPU / VOPD（P.26）

**VOPUT 测试**：
```
① 按照 VOPUT 测试模式，输入 PassCode 进入相应测试模式
② 该模式下，芯片所有 IO 被配置为输出无效（Output Disable），
   同时打开内部上拉电阻（30~50 kΩ）
③ 测试机在每一个 IO 通道上施加低电平，并判断电流
```
| 结果 | 判定 |
|---|---|
| **通过** | 所有 IO 电流 **< 0.1 mA** |
| **失败** | 任何一个 IO 电流 **> 0.2 mA** |

**VOPDT 测试**：
```
① 按照 VOPDT 测试模式，输入 PassCode 进入相应测试模式
② 该模式下，芯片所有 IO 被配置为 Output Disable，
   同时打开内部下拉电阻（30~50 kΩ）
③ 测试机在每一个 IO 通道上施加高电平，并判断电流
```
| 结果 | 判定 |
|---|---|
| **通过** | 所有 IO 电流 **> −0.1 mA** |
| **失败** | 任何一个 IO 电流 **< −0.2 mA** |

> **物理意义**：VOPU/VOPD 测的是**内部上/下拉电阻是否真的存在且阻值合理**。上拉 30~50 kΩ 接 0 V → 电流约 0.07~0.11 mA；下拉 30~50 kΩ 接 3.3 V → 电流约 −0.07~−0.11 mA。

### 5.4 NFL 噪声滤波测试（P.29）

```
① NRST 拉低，重新输入 PassCode，进入 Noise Filter 测试模式
② 该模式下，芯片内部所有 Noise Filter 被串联在一起
③ 在 PA4 输入高电平，测试 PA5 是否为低
④ 在 PA4 输入低电平，测试 PA5 是否为低
```

> **判据的逻辑**：Noise Filter 的作用是**滤除窄脉冲**。所以无论 PA4 给高还是给低，PA5 都应该**保持低** —— 因为滤波后信号不会立即响应。这正是"噪声滤波器工作正常"的证据。

### 5.5 HSE 时钟输入引脚漏电流测试（P.31）

```
① NRST 拉低，重新输入 PassCode，进入测试模式
② 向 HSE_OSCI 施加 3.3 V 电压，向 HSE_OSCO 施加 0 V 电压
③ 判断 HSE_OSCI 电流是否在范围内
```

| Name | Pin | 输入/输出 |
|---|---|---|
| HSE_OSCI | **PF0** | 输入 |
| HSE_OSCO | **PF1** | 输入/输出 |

**Limit**：电流根据**统计结果**给出。**Pass：典型电流约 1 µA。**

> **工程思想**：这类项的限值不是从手册抄的，而是**先测一批好品、统计出分布**再定 —— 这叫"限值的统计确定法"。

### 5.6 PVD 掉电工作模式测试（P.33）

```
① NRST 拉低，重新输入 PassCode，进入 PVDT 模式
② 设置 PVDLVL[2:0] = 0x7（Pattern 中 PA4、PA5、PA6 都设置为高）
③ PVDPD（PA3）拉低后，测量 PVDO（PA7）的电压
④ 若在三个检查点测的电压都符合要求，测试通过
```

| Name | Pin | 输入/输出 |
|---|---|---|
| PVDPD | **PA3** | 输入 |
| PVDLVL0 | **PA4** | 输入 |
| PVDLVL1 | **PA5** | 输入 |
| PVDLVL2 | **PA6** | 输入 |
| PVDO | **PA7** | 输出 |

### 5.7 BIST 内部自建测试（P.35）

```
① 输入 PassCode 进入相应测试模式之后
② BISTRSTN（PA5）拉高
③ 输入 BIST 时钟信号（PA4），频率最大时钟频率 20 MHz
④ RAM1BEN（PA3）拉高后，36100 个 BISTCK
⑤ 观察 RAM1B_DONE（PA7）和 RAM1B_FAIL（PA6）
```

| Name | Pin | 输入/输出 |
|---|---|---|
| RAM1BEN | **PA3** | 输入 |
| BISTCLK | **PA4** | 输入 |
| BISTRSTN | **PA5** | 输入 |
| RAM1B_DONE | **PA7** | 输出 |
| RAM1B_FAIL | **PA6** | 输出 |
| LDO_VDDL_RDY | **PB1** | 输出（不用测试） |

> **注意时序角色的切换**：**PA4 在输入 PassCode 阶段是 PWCLK（BOOT0）作为时钟，在进入 BIST 测试模式后，是 BISTCK（PA4）作为时钟。**

**判定条件**：
| 结果 | 判定 |
|---|---|
| **通过** | **DONE = High，同时 FAIL = Low** |
| **失败** | **DONE = High，同时 FAIL = High** |

> **关键**：以 **DONE 信号为高**作为判定通过或失败的时间点。

### 5.8 HSI 高速晶振频率测试（P.37）

```
输入 PassCode，进入 HSIT 测试模式后，分 2 步：
(1) 拉低 HSI_EN，立即观察 PA7（8MCKO）是否为低
(2) 拉高 HSI_EN，芯片内部 HSI 时钟通过 PA7 输出，
    频率标称值 8 MHz，要求小于 ±2%
```

| Name | Pin | 输入/输出 |
|---|---|---|
| HSI_EN | **PA3** | 输入 |
| 8MCKO | **PA7** | 输出 |

### 5.9 PLL 锁相环频率测试（P.39–P.40）

| Name | Pin | 输入/输出 |
|---|---|---|
| PLLCKI | **PA3** | 输入 |
| SDI_SCK | **PA4** | 输入 |
| SDI | **PA5** | 输入 |
| PLLLOCK | **PA6** | 输出 |
| PLLCKO | **PA7** | 输出 |
| PLLPD | **PB1** | 输入 |

**测试方法（P.40）**：
> 本测试模式的目的是测试芯片内部 **PLL 模块的功能**。**PA3 输入 PLL 的参考时钟**（8 MHz）；**PB1 输入 PLL 的 PD 信号**；PLL 的其它控制信号由 **PA5、PA4 串行输入，一共需要串行输入 37 Bit 的数据**。**PA6 输出 PLL 的 Lock 信号**，**PA7 输出 PLL 的时钟**。
>
> 当 PA3 提供 8 MHz 的参考时钟，PA5-PA4 提供 37 Bit 串行序列 **0x04_4C48_412** 时，等到 PB1 输入变低，**PLL 应该输出 20 MHz 的时钟**。
>
> **Pattern 有两个 Check Point**：
> 1. **串行序列输入完成后、PB1 还没有变低时**，检查 PA6 和 PA7 —— 这时 **PA6 和 PA7 输出应该都为低电平**；
> 2. 然后把 **PB1 输入低电平，等待 100 µs**，检测 PA6 和 PA7 —— 此时 **PA6 输出应该为高电平（Lock），PA7 输出 20 MHz 的时钟**。

> **`0x044C48412` 是本案例最"硬核"的一个数值** —— 37 bit 的 PLL 配置序列，写错了 PLL 就不会锁定。


## 七、测试总结（课件 P.46）—— 全课程最重要的两条"铁律"

### 7.1 永远不要将 DUT 的输入引脚当作输出引脚进行功能测试

> 最常见的是在 Pattern 中，如果一个输入引脚在此测试项不需要去管（既给 0 或给 1 不影响此测试结果），我们有人就给它 **"X"**，而 **"X" 是输出测试的 mask 态**，这样测试机就会将此引脚当作**输出**去处理，连接到比较电路，只是对结果不做比较。
>
> **记住：在功能测试中，输入引脚不能直接测试期望得到 Pass/Fail 的结果；信号施加到输入引脚，我们需要测试的是输出引脚。**

**正确做法**：输入引脚在该测试项不关心时，应给一个**确定的 0 或 1**（或用 `P` 保持上次状态），**不要用 `X`**。

### 7.2 永远不要将测试机的驱动单元连接到 DUT 的输出引脚

> 此举会造成**测试机和器件本身会在同一时间驱动电压和电流到该引脚**，当它们在某一点相遇时，**电流小的一方会受到严重破坏**。

**物理原因**：两个电压源直接并联互相"顶牛"，谁的内阻大、驱动能力弱，谁就被对方灌穿 —— 轻则测试失败，重则**烧毁测试机通道或 DUT**。

## 八、教学重点与易错点

### 8.1 教学重点

1. **"测试模式 + PassCode" 是本案例的灵魂**：13 个测试项里绝大多数都要先切模式。
2. **TMU 第一次登场**：测频不能靠 DIO 比较器，必须用时间测量单元；`.sig` 里的 **Share** 机制（TMU 与 DIO 共用引脚）也要理解。
3. **"统计定限值"的方法**：HSE/LSE 漏电流的 Limit 来自统计结果，不是照抄手册。
4. **Pattern 数量最多（11 个）**：每个测试模式对应一个 Pattern，是"功能测试规模化"的样板。
5. **DFT 概念落地**：BIST 与 SCAN 不再是课本名词，而是 `bist_pat` 里真实的 36100 个时钟周期。

### 8.2 易错点

| # | 易错点 | 说明 |
|---|---|---|
| 1 | **输入脚用 "X"** | 见 7.1，会把输入脚当输出脚处理 |
| 2 | **把驱动单元接到输出脚** | 见 7.2，可能烧器件/烧通道 |
| 3 | **忘记先输入 PassCode** | 不进测试模式，所有 Pattern 都是无意义的 |
| 4 | **PA4 时钟角色搞混** | PassCode 阶段是 PWCLK（BOOT0），BIST 阶段是 BISTCK（PA4） |
| 5 | **PLL 37 bit 序列写错** | `0x04_4C48_412`，且必须先检查"未锁定前 PA6/PA7 都为低" |
| 6 | **BIST 判据看错信号** | 必须 **DONE=High 时**同时看 FAIL：FAIL=Low 才 Pass |
| 7 | **VIH/VIL 用错公式** | 手册 Table 4-9（0.9·VDD）与 Table 4-10（线性公式）在 3.3 V 下差到 2.97 V vs 1.546 V，**用错会大面积误杀** |
| 8 | **NRST 与 BOOT 也拿去测 VOH/VOL** | 整体计划明确"**除 NRST 和 BOOT**" |
| 9 | **等待时间不足** | LSI 要等 **80 µs**，PLL 锁定要等 **100 µs** |
