> **性质**：本仓库六个课程案例之外的**扩展案例**，来自 MINI-ATE 工作区
> `D:\MINI-ATE\workspace\74HC138\`，不是课件配套工程。
> **用途**：验证同一套 ST2500/MINI-ATE 工程体系能否从零搭建一个

> **结果**：TMF 15 个函数、71 个参数，虚拟测试 **71/71 通过**，故障注入 **5/5 命中**。

## 一、器件认识

### 1.1 是什么

**74HC138 是高速 CMOS 3-8 线译码器/解复用器**，把 3 位二进制地址
（A2 A1 A0）译成 8 个输出（Y0~Y7）中的**一个低电平**，其余 7 个为高电平。
输出**反相**：选中为 `L`，未选中为 `H`。

### 1.2 三个使能端（最容易记反）

| 使能 | 有效电平 | 说明 |
|---|---|---|
| **E1** | **低** | 低有效 |
| **E2** | **低** | 低有效 |
| **E3** | **高** | 高有效 |

> 只有 **E1 = 0、E2 = 0、E3 = 1** 时才译码；任意一个无效，**Y0~Y7 全部为高**。
> 很多资料把三个使能写成 `G1 / G2A / G2B`，本工程统一叫 `E1 / E2 / E3`。

### 1.3 真值表（使能有效时）

| A2 | A1 | A0 | 选中输出 |
|:--:|:--:|:--:|:--:|
| 0 | 0 | 0 | **Y0 = L** |
| 0 | 0 | 1 | **Y1 = L** |
| 0 | 1 | 0 | **Y2 = L** |
| 0 | 1 | 1 | **Y3 = L** |
| 1 | 0 | 0 | **Y4 = L** |
| 1 | 0 | 1 | **Y5 = L** |
| 1 | 1 | 0 | **Y6 = L** |
| 1 | 1 | 1 | **Y7 = L** |

使能无效时：**Y0~Y7 = H（全高）**。

### 1.4 与 74HC595 的区别

| 器件 | 类型 | 输出 | 关键控制 |
|---|---|---|---|
| **74HC138** | 组合逻辑译码器 | 反相，选中低 | 3 地址 + 3 使能 |
| 74HC595 | 串入并出移位寄存器 | 锁存并行输出 | SER/SRCLK/RCLK/OE |

74HC138 **没有时钟、没有锁存**，输出随输入组合立即变化 —— 这也是它适合做
「组合逻辑功能 + 传输延时」入门案例的原因。

## 二、工程文件体系

### 2.1 信号映射（`.sig`）

| 信号 | AFEType | ChType | 通道 |
|---|---|---|---|
| A0/A1/A2 | DIO | Inout | `1:1:0` ~ `1:1:2` |
| E1/E2/E3 | DIO | Inout | `1:1:3` ~ `1:1:5` |
| Y0~Y7 | DIO | Inout | `1:1:6` ~ `1:1:13` |
| VCC | **DPS** | Supply | `1:1:0` |
| TMU1/TMU2 | TMU | DEFAULT | `1:1:0` / `1:1:1` |

14 个数字 I/O 全部接 DIO Inout；电源单独用 DPS；时序测量用 TMU。

### 2.2 信号分组（`.grp`）

| 组名 | 成员 | 用途 |
|---|---|---|
| `IO_PINS` | 14 个 I/O | OS、功能电平 |
| `INPUT_PINS` | A0,A1,A2,E1,E2,E3 | IIH/IIL |
| `OUTPUT_PINS` | Y0~Y7 | VOH/VOL |
| `ENABLE_PINS` | E1,E2,E3 | 使能组合 |
| `TMU_PINS` | TMU1,TMU2 | Tpd/Tt |

### 2.3 时序（`.tim`）

| WFT | 周期 | 驱动 | 比较 |
|---|---|---|---|
| WFT1 | 16 ns | `0/1` 在 0 ns | `H/L` 在 10 ns |
| **WFT2** | **500 ns** | `0/1` 在 0 ns | **`H/L` 在 400 ns** |

> 本工程的功能/延时 Pattern **实际都用 WFT2**（500 ns 周期、400 ns 采样），
> 给 74HC138 留出足够的建立/传输时间；WFT1 只作为高速档保留。

### 2.4 Pattern（`.pat` + `pattern/*.csv`）

| # | Pattern | 行数 | 用途 |
|---|---|---|---|
| 1 | `FUNC` | 约 40 | 完整真值表 + 使能组合 |
| 2 | `DEMUX` | 约 20 | E1 作数据输入的解复用 |
| 3 | `ICC` | 2 | 输入全低、输出全高 |
| 4 | `VOH` | 2 | E1=1 禁止译码，输出全高 |
| 5~12 | `VOL_Y0` ~ `VOL_Y7` | 各 2 | 逐个选中 Yn 为低 |
| 13~15 | `DELAY_A0/E3/E1` | 各 6 | 带 `loop_inf` 的延时/转换时间 |

CSV 列：`Label, WFT, Sequence, A0, A1, A2, E1, E2, E3, Y0..Y7`。

## 四、`Test.cpp` 实现要点

### 4.1 统一骨架

```cpp
#include "interface.h"
using namespace std;

const int INPUT_PIN_NUM  = 6;
const int OUTPUT_PIN_NUM = 8;
const int IO_PIN_NUM     = 14;

USER_CODE void FUNC() {
    TEST_BEGIN
        FunctionalPatternTest("FUNC", 4.5, 4.5, 0, 3.15, 1.35, 0);
    TEST_ERROR
        binObj.HandlerException(0);
    TEST_END
}
```

每个测试项都是 `USER_CODE` 导出函数，由 `.tmf` 的 `FuncName` 调度，没有 `main()`。

### 4.2 功能测试的公共函数

`FunctionalPatternTest(patName, vcc, vih, vil, voh, vol, paramID)` 一次完成：

1. `dps.Signal("VCC").Connect()` → `FVMV` 设定 VCC；
2. `pinlevel.Signal("IO_PINS")` 设 `Vih/Vil/Voh/Vol`；
3. `dio.Pattern(patName).SetTimeOut(10000).Test()`；
4. `GetFailResult()` 取 Pattern 比较结果；
5. 下电、断开；
6. `binObj.CheckResultAndBin(paramID, result)`。

`FUNC / DEMUX / FUNC_LIM / FUNC_2V / FUNC_6V` 都复用它，只是 VCC 和电平不同：

| 函数 | VCC | Vih | Vil | Voh | Vol |
|---|---|---|---|---|---|
| `FUNC` | 4.5 | 4.5 | 0 | 3.15 | 1.35 |
| `DEMUX` | 4.5 | 4.5 | 0 | 3.15 | 1.35 |
| `FUNC_LIM` | 4.5 | **3.15** | **1.35** | 3.15 | 1.35 |
| `FUNC_2V` | **2.0** | 2.0 | 0 | 1.4 | 0.6 |
| `FUNC_6V` | **6.0** | 6.0 | 0 | 4.2 | 1.8 |

### 4.3 VOH：用使能端让输出全高

```cpp
// E1 = 1 禁止译码 -> Y0~Y7 全高，不需要跑向量
dps.Signal("VCC").FVMV(4.5);
pinlevel.Signal("IO_PINS").SetVih(4.5).SetVil(0)
                          .SetVoh(3.15).SetVol(1.35);
dio.Pattern("VOH").Test();          // 只是确认输出确实为高
ppmu.Signal("OUTPUT_PINS").SetMode("FIMV")
    .CurrForce(-4e-3)               // 抽 4 mA
    .CurrRange(20e-3).VoltClamp(5, -2);
ppmu.Signal("OUTPUT_PINS").Measure(VOH_RESULT);
```

**技巧**：VOH 不靠逐条向量，而是用 **E1=1 把 8 个输出一次性置高**，
再对 8 个脚同时抽 −4 mA，一次测完。

### 4.4 VOL：逐脚选通，灌 +4 mA

74HC138 同一时刻只有一个 Y 为低，所以 VOL 必须**逐个输出测**：

```cpp
for (int n = 0; n < 8; ++n) {
    dio.Pattern(VOL_PAT[n]).Test();          // 选通 Yn 为低
    ppmu.Signal(VOL_SIG[n]).SetMode("FIMV")
        .CurrForce(4e-3)                     // 灌 4 mA
        .CurrRange(20e-3).VoltClamp(2, -2);
    ppmu.Signal(VOL_SIG[n]).Measure(VOL_RESULT);
    binObj.CheckResultAndBin(n, VOL_RESULT, 1);
}
```

对应 8 个 Pattern：`VOL_Y0` ~ `VOL_Y7`，每个只把目标脚写成 `L`，其余 `H`。

### 4.5 Tpd：TMU 主从通道 + Hold

```cpp
tmu.SetupTmuOutputCh(1, 1, 0, inDioCh);   // TMU0 -> 被测输入
tmu.SetupTmuOutputCh(1, 1, 1, Y0_DIO_CH); // TMU1 -> Y0

dio.Pattern(patName).Run();
dio.Pattern(patName).GetHoldStatus(bHold);
if (bHold) {
    tmu.PinToPinDelay().Signal("TMU_PINS")
        .SetTrigLevel(2.25, 2.25)
        .SetTrigSlope(inSlope, outSlope)
        .SetTimeOut(100).SetVoltClamp(6, -2).Execute();
    tmu.PinToPinDelay().StartMeas();
    tmu.PinToPinDelay().GetMeasResult(timeResult);
    dio.Pattern(patName).SetHoldExit();
}
```

| 路径 | 输入→输出 | 触发沿 |
|---|---|---|
| A0 → Y0 | 反相 | `POS → NEG` / `NEG → POS` |
| E3 → Y0 | 反相 | `POS → NEG` / `NEG → POS` |
| E1 → Y0 | **同相** | `POS → POS` / `NEG → NEG` |

> **易错点**：A/E3 是「输入变高、选中输出变低」的反相关系；E1 是低有效，
> 「E1 变高、输出变高」是同相关系。斜率配反会测到错误的边沿。

### 4.6 Tt：10% / 90% 阈值

```cpp
tmu.RiseTime().Signal("TMU2").SetThresholds(0.45, 4.05) ...; // 10% -> 90%
tmu.FallTime().Signal("TMU2").SetThresholds(4.05, 0.45) ...; // 90% -> 10%
```

VCC=4.5 V 时：10% = 0.45 V，90% = 4.05 V。两个方向各测一次，写入 Param 0/1。

### 4.7 小电流两段式

`ICC / IIH / IIL` 都遵循：**先大量程上电稳定，再切小量程精测**。

```cpp
dps.Signal("VCC").SetMode("FVMI").VoltForce(6).CurrRange(20e-3); // 先 20 mA 充电
sys.DelayUs(2000);
dps.Signal("VCC").SetMode("FVMI").VoltForce(6).CurrRange(20e-6); // 再 20 µA 测
```

直接上 20 µA 量程会因为上电电容瞬态导致读数不稳或超量程。

## 五、Pattern / Timing 设计要点

1. **输入脚给确定值**：`0`/`1`，不要给 `X`。`X` 是输出 mask，会让测试机把该脚接到比较电路。
2. **输出脚给 `H`/`L` 期望值**：不比较时用 `X`，但 74HC138 的 Y 是推挽输出，
   功能向量里建议全部写成期望 `H/L`，便于定位是哪一位错。
3. **一行 = 一个 WFT2 周期（500 ns）**，`H/L` 在 400 ns 采样。
4. **延时 Pattern 用 `loop_inf`**：
   ```
   ,WFT2,nop,0,0,0,0,0,1,X,...
   ,WFT2,loop_inf L1,1,0,0,0,0,1,X,...
   ...
   L1,WFT2,nop,0,0,0,0,0,1,X,...
   ```
   进入 Hold 后 TMU 才有稳定的重复边沿可测；`SetHoldExit()` 退出，继续执行 `stop`。
5. **`.pat` 只登记 Pattern 名与 CSV 路径**，真正向量在 `pattern/*.csv`。

### 6.1 模型行为

- **Pattern**：解析 CSV，按真值表算 Y0~Y7，与 `H/L` 期望比较；`X` 不比较。
- **DPS**：`VoltForce` 更新 VCC；VCC=0 时输出视为不确定。
- **PPMU**：
  - OSN/OSP 返回二极管压降；
  - VOH/VOL 与输出状态关联：对高电平输出抽 −4 mA 得到接近 VCC 的电压，
    对低电平输出灌 +4 mA 得到接近 0 V 的电压；
  - IIH/IIL 返回漏电流。
- **TMU**：按被测通道（A0=0 / E1=3 / E3=5）与触发沿返回延时；Rise/Fall 返回转换时间。
- **Hold**：`Pattern::Run()` 检测到 `loop_inf` 时 `GetHoldStatus()` 为 true，
  `SetHoldExit()` 后继续。

## 七、踩坑清单

| # | 坑 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | 把 E1/E2 当高有效 | 功能全错、输出永远高 | E1/E2 **低**有效，E3 **高**有效 |
| 2 | 在 Pattern 里驱动 Y 输出 | 测试机与 DUT 对顶，读数异常 | Y 只写 `H/L` 比较或 `X`，绝不写 `0/1` |
| 3 | VOH 逐脚跑向量 | 效率低、易漏脚 | **E1=1** 一次让 8 个输出全高，再同时抽 −4 mA |
| 4 | VOL 同时测 8 脚 | 只有被选中的一脚是低，其余是高 | 8 个 Pattern 逐个选通，逐个灌 +4 mA |
| 5 | 电流方向搞反 | VOH 测成 0 V / VOL 测成 VCC | 高电平输出**抽**电流（−4 mA），低电平输出**灌**电流（+4 mA） |
| 6 | Tpd 斜率配错 | 延时偏大/测不到 | A0、E3 反相用 `POS→NEG`；E1 同相用 `POS→POS` |
| 7 | Tt 阈值用 0/4.5 V | 转换时间偏小 | 用 **10%/90%**：0.45 V / 4.05 V |
| 8 | 小电流直接上小量程 | 读数漂、超量程 | 先 20 mA 充电，再切 20 µA 测量 |
| 9 | TMF 单位写成 V | 判定全错 | Tpd/Tt 用 **nS**（1e-9），电流用 µA/mA |
| 10 | Pattern 没加 `loop_inf` | `GetHoldStatus()` 永远 false | 延时/转换时间 Pattern 必须带 `loop_inf` + `stop` |
| 11 | `.pat` 路径写错 | 加载 Pattern 失败 | 用 `.\pattern\XXX.csv` 相对路径，文件名大小写一致 |
| 12 | IDE 里 `Test.cpp` 全红 | 函数名/类型无法解析 | 把 `usrInterface.h`、`usrDataType.h`、`ulargelonglong.h` 复制到工程根目录，或配置 CDT include 路径；再重建索引 |

> 第 12 条是 MINI-ATE 的 Eclipse CDT 索引问题，**不是编译错误**：
> `make` 能生成 `Test.dll` 就说明代码没问题，红色只是索引器没找到 `runner/inc` 的头文件。
