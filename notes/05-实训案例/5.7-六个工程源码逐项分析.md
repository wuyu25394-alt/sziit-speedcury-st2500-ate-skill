## 0. 平台工程体系速览（模板认知）

### 0.1 六类配置文件的分工

| 文件 | 作用 | 谁读它 |
|---|---|---|
| `<工程>.job` | 总入口，串联 ResDef / SigMap / SigGroup / Pattern / Timing / TMF / Library / Makefile | Runner、IDE |
| `<工程>.sig` | 信号 → 仪器类型(AFEType) → 通道类型(ChType) → Site0 物理通道 | 平台资源层 |
| `<工程>.grp` | 把若干信号打包成组名 | `Test.cpp` 里 `xxx.Signal("组名")` |
| `<工程>.res` | 机台槽位上线（OnLine/OffLine）的板卡清单与数量 | 平台初始化 |
| `<工程>.tim` | 波形表（Waveform Table）：周期 + 每信号每个 WFC 的驱动/比较边沿 | Pattern 执行引擎 |
| `<工程>.pat` | Pattern 名 → 向量 csv 路径 的索引表 | `dio.Pattern("名")` |
| `<工程>.tmf` | 生命周期回调名、FuncList 执行顺序、每步 Sbin/Hbin、ResultAnalysis 限值 | Runner 调度 + `binObj.CheckResultAndBin` |
| `Test.cpp` | 全部测试函数与生命周期回调实现 | 编译进 `Test.dll` |
| `interface.h` | `#define USER_CODE extern "C" __declspec(dllexport)` + 平台头 | 编译器 |
| `Makefile` | `g++ -shared -std=c++17 ... -o Test.dll` | 构建 |

### 0.2 AFEType（仪器类型）取值含义

`.sig` 第二列 `AFEType` 决定该信号由哪类硬件资源驱动/测量，第三列 `ChType` 是通道方向属性。

| AFEType | 含义 | 本课程用途 | 对应 API 对象 |
|---|---|---|---|
| `DPS` | Device Power Supply，器件电源，可 FV/FI + 电流钳位 | VDD / VCC / VDDA / 运放正负电源 | `dps` |
| `DIO` | Digital I/O 数字通道，可驱动可比较（Inout） | 输入驱动、输出比较、pinlevel、Pattern | `pinlevel`、`dio` |
| `CBIT` | Control BIT，控制位/继电器驱动 | 切换负载电阻、I²C 上拉、测试通路 | `cbit` |
| `AWG` | Arbitrary Waveform Generator 任意波形发生器 | 生成 `SIN`/`RAMP` 激励 | `awg` |
| `DGT` | DiGiTizer 数字化采集 | 采输出波形算 RMS / 频谱 | `dgt` |
| `BPMU` | Bias/Parametric Measurement Unit。本平台以"站点级 BPMU 资源"提供 PPMU 能力，`ChType` 常写 `Supply`/`In`/`Out` | 运放、LDO 的 DC 参数测量 | `bpmu` |
| `TMU` | Time Measurement Unit，时间/频率测量单元 | 测 HSI / PLL / LSI 频率 | `tmu.Freq()` |
| `RVS` | 参考/电压源类资源（只在 `.res` 出现，本六工程 `Test.cpp` 未直接调用） | 预留 | — |

> 说明：`ppmu` 是"管脚参数测量单元"API 对象，用法是 `ppmu.Signal("引脚或组")`，在硬件上落到 DIO/BPMU/DPS 通道的 PMU 能力上；`bpmu` 则是显式的 BPMU 资源对象。两者模式字符串相同（`FVMV`/`FIMV`/`FVMI`/`FNMV`）。

### 0.3 四种测量模式与两个易混 API

| 模式 | Force | Measure | 课程中的典型用途 |
|---|---|---|---|
| `FVMV` | 电压 | 电压 | 给电源/引脚强制电压，自检、复位 |
| `FIMV` | 电流 | 电压 | 开短路（灌/抽电流看二极管压降）、VOH/VOL |
| `FVMI` | 电压 | 电流 | IIL 漏电、IDD 电源电流、ICC |
| `FNMV` | Nothing（不驱动） | 电压 | 高阻监听节点电压（运放输出、PVD 输出） |

两个易混点：

1. **`CurrRange()` 既定量程也定分辨率**：如 `CurrRange(2e-6)`=2 µA 量程（PPMU 分辨率 0.4 nA），`CurrRange(100e-6)`=100 µA 量程（20 nA）。
2. **`binObj.CheckResultAndBin(site, results, count)` 的第一个参数不是"第几个测试项"，而是 TMF `ResultAnalysis` 数组里的起始 ParamNumber**，`count` 是本次上报的参数个数。CD4511 的 `CheckResultAndBin(0, OSN_RESULT, 14)` 表示从参数 0 起比 14 个。

### 1.8 教学重点与易错点

- **重点**：ATE 工程的最小完整闭环 —— `.sig` 定义信号、`.grp` 打包、`.tim` 定义波形、`.pat`+`csv` 定义向量、`.tmf` 定义顺序与限值、`Test.cpp` 实现方法。全部 DC 项都用 `ppmu` 的三种模式串起来，是最标准的教学骨架。
- **易错点 1**：`ResultAnalysis` 的参数顺序必须与 `Measure()` 回来的结果下标对齐。CD4511 的 14 脚顺序是 `B,C,LT,BI,LE,D,A,Ye,Yd,Yc,Yb,Ya,Yg,Yf`，**不是**通道号顺序，也不是字母顺序。
- **易错点 2**：`OSN_T`/`OSP_T` 里 `ppmu.Signal("INOUT_PINS").Connect()` 之后又用 `SetMode("FVMV")` 先把所有脚拉到 0 V，若省略这一步，测二极管压降会被残余电荷污染。
- **易错点 3**：`VOH_T` 的 `VoltClamp(6, 0)` 下限是 0，`VOL_T` 的 `VoltClamp(6, -1)` 下限是 -1；两者不对称是刻意的（VOL 测低电平需要能拉到负向以判定失效）。
- **易错点 4**：`binObj.CheckResultAndBin(0, FUNC_RESULT)` 没有第三个参数（因为 FUNC 只有 1 个参数）。
- **易错点 5**：本工程 `Makefile` 多链了 `-lShmoo`，但 `Test.cpp` 未使用 Shmoo 功能，属于模板残留。

### 2.8 教学重点与易错点

- **重点**：AWG + DSIO 的"模拟激励 → 数字采样 → 软件 DSP"闭环，是整份课程里唯一讲**混合信号测试**的工程。AWG 的 `GenerateTypWave("RAMP"/"SIN", ...)` 与 `SetMode(...)` 参数含义（波形点数、循环数、触发方式）是核心知识点。
- **重点**：`SetSampleBits(8)`、`SetSampleEdge(2048)`、`SetSampleSignal("DO")` 三个参数决定 DSIO 的采集口径。
- **易错点 1**：`trip_volt[i] = trip_point[i]*(5.0/2048.0)` 中的 5.0 是 AWG 幅度（`SetAmpl(5)`），改幅度必须同步改这个常数，否则 INL/DNL 全错。
- **易错点 2**：`LSBdut=(Vfst-Vzst)/(256.0-2.0)` 用码 254 与码 0 两点算增益，而不是 255，是刻意避开满量程端点的做法，不能"顺手改成 255"。
- **易错点 3**：`max_dnl`/`max_inl` 的取法用 `abs` 比较后取**带符号值**，逻辑上取的是"绝对值较大的那个带符号值"，结果依赖于遍历顺序，是算法实现上的坑。
- **易错点 4**：`ADC_Static_AWG` 里 `POWER_OFF()` 被调用了两次（正常结束处一次 + `TEST_ERROR` 前一次），属于冗余但无害。
- **易错点 5**：`reverse()` 未使用；`.pat` 里 `ADC_CH0`/`ADC_CH1`/`ADC_CH1_DYNAMIC`/`..._EXPAND` 4 条登记未被调用。
- **易错点 6**：目录里另有 `ADC0832_FT_V01.tmf.bak`（旧版本，FuncList 为 `OS_TEST` / `ADC_Static_PPMU` / `ADC_Static_AWG` / `SetPassBin`），说明静态 ADC 测试曾用 PPMU 版本，现改用 AWG 版本 —— 对比阅读可理解两种方案差异。
- **易错点 7**：`datalog\` 下保留了大量历史输出（`adc_ouput.txt` 1.2 MB、`111.csv`、`.xlsx` 等）与 `AWG\awd\` 波形缓存，`.job` 的 `IncDir` 把 `./AWG/`、`./AWG\awd/`、`./datalog/` 都加进了头文件路径，属于工程调试遗留。

### 3.8 教学重点与易错点

- **重点**：**用数字 Pattern 表达 I²C 协议**。SCL/SDA 的每一位都由 CSV 逐拍写出，配合 `.tim` 里的 `Z` 状态和 `PUUL_HI_CBIT` 上拉，实现真实开漏总线；这是理解"协议类器件如何做 ATE 功能测试"的最佳范例。
- **重点**：**软件平均降噪**。`standby` 的 100 次测量 + `FOR_EACH_SITE_START/NEXT_SITE` 宏是本课程唯一展示多站点安全累加写法的地方。
- **易错点 1**：本工程**没有 DPS**，电源由 `VCC_DIO`（DIO/BPMU）提供，量程只能开到 `3.0e-2`（30 mA）。如果要测更大电流必须改硬件通路，不能照抄其它工程的 `CurrRange(0.5)`。
- **易错点 2**：`WRITE_55AA_HV` 必须先 `SetOn` 上拉继电器再 `pinlevel.Connect()`，顺序反了总线会浮空、Pattern 首字节就可能失败。
- **易错点 3**：漏电测试必须"大量程过渡 → 小量程（2 µA）精测"，代码里 `VoltForce(0)` 出现两次（一次配 2.0e-2、一次配 2.0e-6），省略第一次会让量程切换时产生电流冲击。
- **易错点 4**：`standby` 里测的是 `VCC_DIO` 的电流，但循环里 `ppmu.Measure(N1_PPMU_RESULT)` 没有指定信号 —— 平台按"最后一次设置的对象"返回，因此循环前那条 `VCC_DIO ... CurrRange(2.0e-6)` 不能删。
- **易错点 5**：`leakage` 与 `standby` 的结果变量都复用了 `N1_PPMU_RESULT`，且 `CheckResultAndBin` 用不同起始下标（0/2 vs 0）区分参数段，读代码时容易看错对应关系。
- **易错点 6**：`.tim`（840 ns 比较点）与 `pattern\I2C_wft1.CSV`（700 ns）两套时序并存，若误用后者会导致 I²C 建立/保持时间判据错位。

### 4.8 教学重点与易错点

- **重点**：**混合信号 MCU 的 FT 测试全景** —— 引脚 OS → 数字电平 Pattern（VOH/VOL）→ 驱动能力（VOPU/VOPD）→ 噪声容限（NFL）→ 模拟模块（HSE/PVD）→ 数字自测（BIST）→ 时钟频率（HSI/PLL/LSI，用 TMU）。
- **重点**：**TMU 频率测量的三套参数**很有教学价值：HSI 用 `SetArmSize(0)`（立即启动）、LSI 用 `SetTimeOut(4000)`+`SetArmSize(10)`（低频需长超时）、PLL 用 `SetArmSize(150)` + `Run()/GetHoldStatus()/SetHoldExit()` 与 Pattern 握手（因为 PLL 需要稳定时间，不能让 Pattern 直接跑完）。
- **重点**：`SetLevel()` 里 `SetVoh(v*0.7)`、`SetVol(v*0.3)`、`SetVt(v*0.5)` 是**按电源比例自动缩放**比较电平的写法，比硬编码阈值更通用。
- **易错点 1**：`OSN_TEST` 里 `ppmu.Signal("LVLPINS_GRP").Connect()` 却对 `OSPINS_GRP` 执行 `FIMV`。两个组的成员列表恰好完全相同（17 脚），所以功能上没出错，但这是**复制粘贴留下的不一致**，一旦两个组被改成不同成员，此处就会静默失效。
- **易错点 2**：`VOPU_TEST` 的 `PA3` 上限是 **-60** 而非 -66（TMF 中单独放宽），代码侧无任何特殊处理，只能靠 TMF 体现 —— 说明该脚的灌电流能力偏弱。
- **易错点 3**：`NFL_TEST` 的 `NFL_PA4_HIGH` / `NFL_PA4_LOW` 命名与代码执行顺序**相反**（先做 `PA4=0V` 存进 `NFL_RESLUT1` 判参数 0，再做 `PA4=3.3V` 存进 `NFL_RESLUT2` 判参数 1），命名与语义容易读反。
- **易错点 4**：`PLL_TEST` 中若 `bhold` 为 false，`MEAS_RESULT` 是**空向量**，`CheckResultAndBin(0, MEAS_RESULT, 1)` 仍会被调用 —— 这是潜在的空判风险。
- **易错点 5**：`#define WAIT_TIME 100000` 定义了但全文未使用。
- **易错点 6**：`OSN_TEST`/`OSP_TEST` 结束时用 `FNMV` 而非 `FVMV 0V`，与其它工程的复位风格不同；`PowerOff()` 里 `ppmu` 用的是 `1.0e-3` 量程而不是 `30e-3`。
- **易错点 7**：`pattern\rom_pat.csv`、`adc_pat.csv` 引用的时序表名（`ROMTWFT1`/`ADC_TIMING`）在 `.tim` 里不存在，不能直接拿去跑。

### 5.8 教学重点与易错点

- **重点**：**用直流法测交流指标**。CMRR / PSRR / Aus 都是"改一个条件测输出电压差，再用 `20*log(1000*abs(1/ΔV))` 换成 dB"。理解 `1000*abs(1/ΔV)`（把 mV 化的读数转回 V 的倒数）是弄懂这三项的关键。
- **重点**：**测量平均与复测**：`MEAS_AVG, 100, 10`（Uos/Ios，快而少）与 `MEAS_AVG, 500, 500`（CMRR/Aus/PSRR，慢而多）两种配置，体现精度与时间的权衡。
- **重点**：**多站点安全写法**：`FOR_EACH_SITE_START(SITE, SITE_ID) ... NEXT_SITE` 把"按站点取平均/换算"写成站点循环，而不是假设单站。
- **易错点 1**：`Ios` 的换算 `abs(...)/(1000*2000)*1000000000` 里，分母的 `1000*2000` 来自"V→mV 的 1000"和"外部 2 kΩ 等效电阻"两个来源，改任何一个硬件参数都必须同步改这个常数。代码里没有任何注释说明，属于本工程最难维护的一行。
- **易错点 2**：`Uos` 的代码注释说单位换算"除以 1000"，得到的结果再与 TMF 的 `-1 ~ 1 V` 比较；而 `bpmu` 返回的原始值单位是平台内部单位（mV 级），因此这里的 `/1000` 是"平台单位 → V"的换算，不是字面意义的 mV→V。
- **易错点 3**：`CMRR` 与 `PSRR` 的函数体几乎逐行相同（只差 DPS 通道组合的语义），`Aus` 与它们也高度相似 —— 极易混淆。读代码时必须靠"改了哪个 DPS 组合"来区分。
- **易错点 4**：每个函数里都声明了一堆**从未使用**的变量：`ST_MEAS_RESULT stMeasVaule, stMeasVaule1, CMRR/Aus/PSRR/I0/I1/icc`、`unsigned long aaa`（在 `Ios_Uos_TEST` 里）。这些是模板残留。
- **易错点 5**：`icc` 里 `dps.Signal("DPS1")` 与 `dps.Signal("DPS0")` 交替使用 `FVMV` 和 `FVMI`；先 `FVMV 2.5V` 再切 `FVMI` 是为了用 DPS 自身测电流，**量程必须先 0.5 再切 0.025**，直接上小量程会因上电浪涌而钳位。
- **易错点 6**：`POWER_OFF()` 用的是 `FVMV 0`，而 `.res` 里 DPS 资源数是 4 —— 正好对应 `DPS_GRP` 的 4 个成员，改信号数量要同步确认 `.res`。
- **易错点 7**：`AWG` 与 `DGT` 在 `.sig` 里定义了却完全未使用，说明本工程是从更完整的方案裁剪出来的。

### 6.8 教学重点与易错点

- **重点**：**用 CBIT 切换功率负载**。K3=250 Ω 对应 ≈10 mA，K4/K5=6.25 Ω 对应 ≈400 mA；同一套 DPS/BPMU 硬件靠继电器覆盖轻载与重载两种工况，是 LDO 测试的标准套路。
- **重点**：**DC 参数测试的"两档对比法"**。LNR 比 3.0 V 与 5.5 V 两点输出；LDR 比 1 mA / 10 mA / 400 mA 三点输出；VOUT 比 2.7/4.0/5.5 V × 10 mA/400 mA 六点。
- **重点**：**AWG+DGT 的交流注入法**：`awg.GenerateTypWave("SIN", ...)` + `dgt.SetCapture(点数, 触发比例)` + `CalcRMS()`，最后 `20*log(1/rms)` 得到 PSRR。参数差异（20000 点 vs 200 点）对应 100 Hz 与 10 kHz 两个频点。
- **易错点 1**：**`PSRR_TEST` 的 `LoopCount=0`**。代码写得很完整（含 AWG/DGT），但 TMF 里这一项被关闭，**默认运行时不会执行**。要启用必须把 `LoopCount` 改成 1。
- **易错点 2**：`VOUT_TEST` 的 `ParamNumber=2` 名叫 `VIN2_5V_10MA`，但代码第三点实际是 **5.5 V**（`VoltForce(5.5)`）。参数命名与实际条件不符，是历史遗留的文档错误。
- **易错点 3**：`VDO_TEST` 计算的是 `2.4 − Vout`（单位为 **V** 量级），却与 TMF 中 `0~200`（**mV**）比较。若读数单位是 V，则 0.1 V 会被当成 0.1 去和 200 比，永远通过 —— **量纲不匹配**是本工程最容易埋雷的地方，实际使用前必须核对 `dbValue` 的单位约定。
- **易错点 4**：`LDR_TEST` 第 455 行 `bpmu.Signal("OUTB").SetMode("FNMV");` **漏写了 `.Execute()`**，导致该次模式切换可能未生效即进入 `K4 SetOn()` 与下一次测量。
- **易错点 5**：`ICL_TEST` 除以 `3.1` 的常数来源不明（疑似分流电阻/增益系数），没有注释；`LDR_TEST` 除以 `6.25` 同理（对应 6.25 Ω 负载电阻）。
- **易错点 6**：`IGND_TEST` 里 `ppmu.Signal("GND").SetMode("FVMI").CurrRange(0.0)` 的复位量程是 0，属于异常值；`SiteResetName0` 里也把 `EN_GND`、`OUTB`、`IN_OUT_DPS` 三组一起 `DisConnect`，但 `IGND_TEST` 中途又重新 `Connect`，通路状态切换频繁，容易漏掉某个继电器。
- **易错点 7**：`OS_TEST` 里 `CheckResultAndBin` 用下标 **0 和 2**（跳过 1），对应 TMF 中 `IN`(0)、`OUT`(1)、`EN`(2) 的分段上报方式——两次调用分别上报 `IN/OUT` 两项和 `EN` 一项。
- **易错点 8**：`PSRR_TEST` 的 `TEST_ERROR` 段里做了 `awg.Stop()` 与 `cbit.Signal("Grp_CBIT").SetOff()` 兜底，是全课程唯一在异常分支里做硬件收尾的写法，值得作为范例。

### 7.5 共同套路（六工程通用的写法）

1. **导出与调度**：`interface.h` 里 `#define USER_CODE extern "C" __declspec(dllexport)`；所有测试函数用 `USER_CODE void xxx()` 导出；`.tmf` 的 `FuncList[].FuncName` 按名字调用。**没有 `main()`**。
2. **异常保护三段式**：`TEST_BEGIN` → 业务 → `TEST_ERROR` / `binObj.HandlerException(0)` → `TEST_END`。LM358P 与 TPS73625 的辅助函数（`POWER_OFF` 等）反而写成普通函数。
3. **辅助函数抽象电源与电平**：`POWER_ON/POWER_OFF`（ADC0832）、`PowerOnVdd/PowerOnVdda/SetLevel/PowerOff`（HK32F031）、`POWER_OFF`（LM358P）。数值上高度一致：DPS 常用 `CurrRange(0.5)` + `CurrClamp(0.5, -0.5)`，下电统一 `VoltForce(0)`。
4. **开短路的固定配方**：VDD/VCC 拉 0 V（或直接以 PCB 地为参考），PPMU 对全部 I/O `FIMV` 灌/抽 ±100 µA（HK24C02 用 -100 µA/-300 µA，ADC0832 用 ±200 µA），`CurrRange` 与 `CurrForce` 同量级，`VoltClamp(2, -2)`，限值 -1.5/-1.2/-1.1 ~ -0.2 V（负向）与 0.2~1.2 V（正向）。
5. **小电流测量的两段式换挡**：先大量程（`40e-3`/`2.0e-2`/`5.0e-4`）稳定，再切小量程（`2e-6`/`10e-6`/`5e-6`/`1e-6`）精测。CD4511 `IIL_T`、HK24C02 `leakage`/`standby`、LM358P `icc` 都是这个套路。
6. **判 bin 的统一定式**：`binObj.CheckResultAndBin(起始ParamNumber, 结果向量, 参数个数)`；通过判定用 `binObj.SetBin(1)` 放在单独的 `SetPassBin` 函数里，`.tmf` 中永远排在最后且 `Sbin=Hbin=1, Results="Pass"`。
7. **复位与断开纪律**：每个测试项结尾都把 force 归零、`DisConnect()`、CBIT `SetOff()`，再 `sys.DelayUs(...)` 等稳定；站点级复位（`site_reset`/`SiteResetName0`）做统一的资源断开兜底。
8. **等待时间的量级**：单点稳定普遍 1000~5000 µs，电源上电/继电器切换 8000~10000 µs，大电容负载或低频稳定用 15000~30000 µs（TPS73625 `LNR_TEST` 用到 30 ms）。

### 7.6 六个工程里最值得提醒的"坑"速查

| 工程 | 坑 |
|---|---|
| CD4511_v1 | `ResultAnalysis` 参数顺序 = 测量下标顺序，不是通道号顺序 |
| ADC0832_FT_EDU_V3 | TMF 声明 6 个静态参数但只判 5 个；`trip_volt` 里的 `5.0` 必须跟随 `SetAmpl(5)` |
