## 一、概念类误区（最容易"想当然"）

### 1.1 通道号 `1:1:0` 到底怎么读

| 说法 | 是否权威 |
|---|---|
| ❌ "板卡 : 站点内资源 : 通道" | 部分实训工程说明文档的**不准确表述** |
| ❌ "板卡 : 资源 : 通道" | 同上 |
| ✅ "**Adapter（机头）: FBID/Slot（业务板）: Channel（通道）**" | **手册 P.83 + 课件3 P.19 的一致定义** |

**要点**：**不含"资源类型"层**。资源类型由 `.sig` 文件的 **`AFEType` 字段单独指定**。
例如 `PA0 信号使用 1 号机头的 Slot1 上的 DIO6 通道` → `AFEType = DIO`，通道 = `1:1:6`。

### 1.2 Pattern 里的 `X` 不能乱用在输入脚

> **"X" 是输出测试的 mask 态。** 如果一个输入脚在某测试项不关心，给了 `X`，测试机会把它**当作输出**处理、接到比较电路（只是不比较结果）。

**正确做法**：输入脚不关心时给**确定的 0 或 1**，或用 `P`（保持上一行状态）。**只有输出脚才用 `X`。**

### 1.3 不要把驱动单元接到 DUT 的输出脚

> 会造成**测试机和器件本身同时驱动电压/电流到该引脚**，当它们在某一点相遇时，**电流小的一方会受到严重破坏**。轻则测试失败，重则烧毁通道或 DUT。

### 1.4 `.pat` 不是 `.tmf` 的一部分

| | `.pat` | `.tmf` |
|---|---|---|
| 有无顺序 | ❌ 无 | ✅ 有 |
| 有无限值 | ❌ 无 | ✅ 有 |
| 有无 Bin | ❌ 无 | ✅ 有 |
| 数量关系 | 少 | **多**（DC 参数项根本不经过 `.pat`） |

**反例**：CD4511 只有 1 个 Pattern，但 `.tmf` 有 8 项 —— **不要以为 Pattern 数 = 测试项数**。

### 1.5 `.tim` 与 `.pat` 是空文件 ≠ 工程损坏

**LM358P 与 TPS73625 两个工程的 `.tim` 与 `.pat` 都是 0 字节空文件**，因为它们是**纯 DC / 静态参数测试，不需要 Pattern**。这是**正常现象**。

### 1.6 `PSRR_TEST` 的 `LoopCount = 0` 是故意的

TPS73625 工程里 `PSRR_TEST` 的 `LoopCount = 0`，**默认不执行** —— 因为它是唯一需要 **AWG + DGT** 且耗时最长的项。**不是配置错误**。

## 二、测量方法类陷阱

### 2.1 小电流测量必须"先大量程，再切小量程"

所有工程的代码都是这个套路：**先用大量程让电路稳定，再切到小量程（2 µA / 5 µA / 10 µA / 1 µA）精测**。

**直接上小量程的后果**：上电瞬态或电容充电会让读数超量程或剧烈跳动。

### 2.2 OS 测试前必须把电源置 0 V

CD4511 的 `OSN_T` / `OSP_T` 都先把 **VDD = 0 V**、各 I/O 置 0 V，然后才加压测流。**否则电源脚的保护二极管会引入额外通路，污染测量结果。**

### 2.3 VOH 抽电流、VOL 灌电流，方向不能反

| 项 | 方向 | 极性约定 |
|---|---|---|
| **VOH / IOH** | **抽**电流（从 DUT 流出） | IOH 一般为**负向** |
| **VOL / IOL** | **灌**电流（流入 DUT） | IOL 一般为**正向** |

**极性约定（课件 P.7）**：**流出 ATE 的电流为正电流，流入 ATE 的电流为负电流。**

### 2.4 CMCC 与 PSRR 的激励方式不同

| 参数 | 对电源做什么 |
|---|---|
| **CMRR** | 两端**同向**上移（共模电压变化） |
| **PSRR** | 两端**反向**拉开（总电源电压变化），共模保持不变 |

> ⚠️ **课件笔误**：《9.课件-LM358》P.34 的 PSRR 测试计划里写成了"算得芯片的**共模抑制比**（范围：>65dB）"，但激励方式是 V+ +0.5 V / V− −0.5 V，**按定义应为 PSRR**。

### 2.5 精测模拟参数要用"差值法 + 多次平均"

来自 LM358 案例的三条实战经验：

| 问题 | 解法 |
|---|---|
| Uos / Ios 数据波动大（µV / nA 级，接近噪声地板） | **多次测量取平均** |
| CMRR 在输入 0 V 时输出不为 0（测试机误差 or 芯片本来就偏） | 把"绝对值测量"改成**差值法** |
| 开环增益测不到（输入 1 µV 就饱和） | **先二分法锁定线性工作区**，再用差值法 |

### 2.6 大电流负载用电阻替代电流源，用 BPMU 的 FN 模式读电压

> LDO 带负载输出时电流较大（TPS73625 要 400 mA），当 ATE 资源本身不满足拉取电流需求时，**可以使用合理的电阻负载替代**（2.5 V / 400 mA = **6.25 Ω**），使用 **BPMU 采用 FN 模式**（即 `FNMV`，不强制任何量、只测电压）测量输出电压。

### 2.7 ADC 量产测试的"单阈值设定"技巧

ADC0832 静态/动态测试中，**DO 的采样电平 VOL = VOH = 2.5 V**（即 VCC/2）：
- 输出高于 2.5 V → 采集为 H；
- 输出低于 2.5 V → 采集为 L。

**等价于用 DIO 比较器实现了一个 1 bit ADC**，从而能把 ADC 的串行数字输出流还原成数字码。**如果把 VOH 和 VOL 设成不同值，采集到的码就会错。**

### 2.8 ADC 动态测试必须用 DSIO 高速采样

普通 DIO 采样率不够，动态参数（SNR/THD/SINAD/ENOB）必须用 **`DSIO`** 模式采集。

### 2.9 测通道漏电必须停时钟

ADC0832 的 **IOFF / ION（通道漏电 ±1 µA）必须在停止时钟的条件下测量**，否则测到的是开关切换电流。

### 2.10 上拉电阻会让 OS 与漏电流测试失效

**HK24C02 案例的核心矛盾**：

```
功能测试：SDA 需要上拉电阻（I²C 开漏输出无法自己拉高）
DC 测试：上拉电阻提供了一条到 VCC 的低阻通路，
         测到的"漏电流"其实是上拉电流 → 测试完全失效
```

**解法**：用 **CBIT 控制的继电器物理断开/连接上拉电阻**（平台侧 RL14 / CBIT0）。

## 三、工程配置与代码类问题（实测发现）

### 3.1 三处真实的配置/代码不一致

| 工程 | 问题 | 后果 |
|---|---|---|
| **ADC0832** | `.tmf` 声明了 **6 个**静态参数（含 `ADC_OUT_Lin`），`Test.cpp` **只判前 5 个** | 最后一个参数**永远不判限** |
| **TPS73625** | ① `VDO_TEST` 用 (2.4 − VOUT) 的 **V 量级**去比 **0~200 mV** 的限值；② `LDR_TEST` 第 455 行**漏写 `.Execute()`** | ① 判限可能永远 Pass；② LDR 计算可能不生效 |
| **HK32F031F4P6** | ① `OSN_TEST` 中 `Connect` 用 `LVLPINS_GRP` 而 `FIMV` 用 `OSPINS_GRP`（两组恰好同成员）；② `PLL_TEST` 在 `bhold = false` 时用**空结果向量**判 bin | ① 暂时无害；② 隐患 |

> **学习价值**：这三个都是**很好的代码审查练习题** —— 能自己发现它们，说明你真的读懂了工程。

### 3.2 参数个数必须与 `.tmf` 一致

`.tmf` 的 `ResultAnalysis` 中的参数顺序与**测量结果向量下标对齐**，`CheckResultAndBin` 的参数个数必须与之一致。

**教训（来自三个工程）**：改了 `.tmf` 的 Sub Test 数量却忘了改代码里的 `CheckResultAndBin` 个数，就会**判错参数或漏判**。

### 3.3 工程路径换机器后要改三处

| 文件 | 要改的字段 |
|---|---|
| `.job` | `AteHomePath`、`jobDir`、`jobFilePath` |
| `Makefile` | `RUNNER_HOME`（默认 `d:/MINI-ATE/runner`） |
| `.cproject` | include 路径（`D:/MINI-ATE/runner/inc` + MinGW 路径） |

### 3.4 备份与残留文件会干扰阅读

6 个工程目录里都存在 `- 副本`、`.bak` 等备份文件（如 `HK24C02_EEPROM_CP1_EDU_V3 - 副本.pat`、`ADC0832_FT_V01.sig.bak`、`rom_pat - 副本.csv`）。**它们不影响运行，但会让目录看起来杂乱，且副本 `.pat` 里的 Pattern 数量可能与正式文件不同**（例如 HK24C02 正式 `.pat` 3 个、副本有 17 个）。**看代码时要确认自己在看哪个文件。**

## 四、器件与手册口径冲突（需原厂澄清）

### 4.1 CD4511 课件自身矛盾

| 位置 | 说法 |
|---|---|
| 课件 P.7 引脚表 | **3=A2、4=A3、6=BI、7=LT** |
| 课件 P.8 文字 | "**BI：4 脚**是消隐输入控制端"、"**LT：3 脚**是测试输入端" |

**采用**：以 P.7 引脚表 + 数据手册 + 工程 `.sig` 为准，即 **6=BI、7=LT**。

### 4.2 CD4511 的 OS / VOH / IIL 限值：课件 vs 工程

| 参数 | 课件 P.15 | 工程 `.tmf` |
|---|---|---|
| OSP / OSN | 0.2 ~ **0.8** V / **−0.8** ~ −0.2 V | 0.2 ~ **1.2** V / **−1.2** ~ −0.2 V |
| VOH | **4 ~ 6** V | **3.9 ~ 5** V |
| IIL / IIH | **±1 µA** | **±0.1 µA** |

**以工程为准**（限值常由实测统计确定），但要知道课件讲的是更紧的理论值。

### 4.2.1 ⚠️ 更严重的一种：课件数值物理上不可能

**ADC0832 的 ENOB**：

| 来源 | ENOB 限值 |
|---|---|
| 课件《12.课件-ADC0832》测试计划表 | **12 ~ 16 bit** |
| 工程 `.tmf` | **7 ~ 8 bit** |
| 物理上限（8 位 ADC，SINAD 理想值 49.9 dB） | **8 bit** |

**结论：课件是错的。** ADC0832 是 8 位 ADC，`ENOB = (SINAD−1.76)/6.02`，**12~16 bit 在物理上不可能** —— 这一栏几乎肯定是从 12/16 位 ADC 的模板里沿用未改。

> **教训**：**当课件数值与物理常识冲突时，相信物理、怀疑课件。** 这也说明工程 `.tmf` 才是"真正在跑的东西"。

### 4.2.2 处理原则

| 情况 | 做法 |
|---|---|
| 课件与工程限值不同 | 以**工程 `.tmf`** 为准 |
| 课件数值物理上不可能 | **相信物理，怀疑课件**（课件模板复用是常见错误源） |
| 课件内部自相矛盾 | 找**第三种资料**仲裁（数据手册 / 工程文件 / 实物） |
| 手册有两套规格 | **问原厂**，不要自己挑一个用（如 HK32F031 的 VIH/VIL） |

六案例的完整限值对照表见 [5.0 第 6.2 节](../05-实训案例/5.0-六案例总览与横向对比.md)。

### 4.3 HK32F031F4P6 的 VIH / VIL 有两套规格

| 来源 | VDD = 3.3 V 时的 VIH |
|---|---|
| 数据手册 Table 4-9 | **0.9 × VDD = 2.97 V** |
| 数据手册 Table 4-10 | 线性公式 → **1.546 V** |

**差异极大，直接决定误杀率。** 遇到这种情况必须**向原厂确认**，不能自己挑一个用。

### 4.4 HK24C02 缺少 5 V 的 AC 规格

首页 FEATURES 声称 5 V 时可达 **1 MHz**，但 **AC 特性表只给了 1.8 V / 2.5 V 两档**，**没有 5 V 档的 tLOW / tHIGH 限值**。

**不可从 2.5 V 档外推** —— 遇到这种手册缺口，要么按 2.5 V 档保守测，要么要原厂补数据。

### 4.5 LM358 的 VOS 按型号与温度档分档

| 版本 | VOS | IB |
|---|---|---|
| **B 版** | **±3 mV** | **−35 nA** |
| **基础版** | **±7 mV** | **−250 nA** |

课件表格给的 **9 mV** 是特定条件下的 Max。**限值必须按型号 + 温度档分档取**，混用会误判。

### 4.6 ADC0832 的 ICC 是型号专属值

**ADC0832-N 的 ICC ≤ 6.5 mA**，**不要与 0831 / 0834 / 0838 的 2.5 mA 混用**。

### 4.7 开机顺序两套手册口径不同

| 来源 | 说法 |
|---|---|
| 简明教程 | 测试机与工控机"**顺序没要求**" |
| 实训平台手册 | **必须先控制主机，再测试机头** |

**建议按后者执行**。

### 4.8 型号写法差异

- TPS73625**DCQR** / TPS73625**DCOR**
- ADC0832**CCN** / ADC0832**NOP8** / ADC0832**NOPB**

手册原文如此，**订料与查手册时要注意**。

## 六、通用器件接口板的手工接线风险

CD4511 是本课程**唯一需要自己用杜邦线搭电路**的案例：

1. **接线错误是最常见的"测试失败"原因** —— 先怀疑接线，再怀疑代码。
2. **CD4511 的 DUT 板原理图与"引脚→测试机通道"对应表在课件里是图片**，文本无法恢复；实训平台手册正文的实验案例其实是 **HK24C02**（第 3.1~3.5 节），**全文没有 CD4511 章节**。因此 CD4511 的走线方法需要**按 32 针插槽定义推导**，不是手册原表。
3. **CD4511 需要接共阴极数码管**（或其等效负载），否则 VOH/VOL 的负载条件与手册不符。
4. **上电前先量通路**：用万用表确认无短路再上电。

## 七、一张"排错决策树"

```
测试全程 Fail
├─ Load 就失败/Project 变红？
│   └─ 没有先 Build。Ctrl+B 编译成功后再 Load
├─ 单个测试项全 Fail
│   ├─ 电源没上？→ 检查 POWER_ON / DPS 的 Force 值与量程
│   ├─ 继电器没切？→ 检查 CBIT SetOn/SetOff 与 K 编号
│   ├─ 上拉电阻没断？→ 漏电流/OS 类测试的典型陷阱（HK24C02）
│   ├─ 量程不对？→ 小电流是否先大量程后切小量程
│   └─ 等待不够？→ 大电容 >1 µF 时需要更长稳定时间（15~30 ms）
├─ 结果不稳定、跳动大
│   ├─ 多次测量取平均（nA/µV 级必须做）
│   ├─ 改用差值法（消除系统性失调）
│   └─ 增加延时
├─ 判限永远 Pass（疑似没判）
│   └─ 检查 CheckResultAndBin 的参数个数是否与 .tmf 的 Sub Test 数一致
├─ 功能测试 Fail 但 DC 都 Pass
│   ├─ Pin Level 设错？（VIH/VIL/VOH/VOL 从 Datasheet 抄）
│   ├─ Timing 的比较沿位置不对？
│   ├─ Pattern 里输入脚误用了 "X"？
│   └─ 忘记先输入 PassCode 进测试模式？（HK32F031、HK24C02）
└─ 完全不知从哪查
    └─ 打开 Text Log（按测试项目分类的详细数据），比 Table Log 更易定位
```

## 八、十条"背下来"的铁律

1. **先 Build，再 Load。** 一次只能 Load 一个工程。
2. **OS 测试永远放第一项。**
3. **测电压用 FIMV，测电流用 FVMI。**
4. **VOH 抽电流（负向），VOL 灌电流（正向）。**
5. **小电流先大量程，再切小量程。**
6. **输入脚不要给 `X`；驱动单元不要接输出脚。**
7. **上拉电阻必须能物理投切，否则 DC 测试全废。**
8. **精测模拟量：多次平均 + 差值法 + 二分法锁定工作区。**
9. **参数个数必须和 `.tmf` 的 Sub Test 数量一致。**
10. **遇到手册数据缺失或自相矛盾，先怀疑"是图片没提取出来"，再怀疑"手册冲突要问原厂"。**
11. **课件数值与物理常识冲突时，相信物理、怀疑课件**（如 8 位 ADC 的 ENOB 不可能是 12~16 bit）；**工程 `.tmf` 才是真正在跑的东西**。
12. **同一门课的不同资料必须交叉对照** —— 使用手册只给了 SMU 的定义，完整规格藏在电源模块课件的图片表里。
