## 三、难度与学习顺序建议

```
第 1 步  CD4511        —— 最简：1 个 Pattern、7 个 DC 项，把"工程文件体系 + DC 测试"跑通
第 2 步  HK24C02       —— 引入 I²C 协议、Pattern 数量上升、学会"上拉电阻与 DC 测试的矛盾"处理
第 3 步  LM358         —— 跳出数字世界：模拟参数（失调、增益、CMRR、PSRR）、辅助运放 + 继电器切换
第 4 步  TPS73625      —— 综合：大电流负载、多继电器切换、AC（PSRR）与 DC 混合
第 5 步  HK32F031F4P6  —— 最复杂：14 个测试项、PassCode 测试模式、TMU 测频、11 个 Pattern
第 6 步  ADC0832       —— 最高阶：AWG 激励 + 高速采集 + 自行实现 FFT 与 INL/DNL/SNR/ENOB 算法
```

## 四、六案例的"共同套路"（来自 6 个工程源码的横向归纳）

### 4.1 代码骨架

```cpp
// interface.h
#define USER_CODE extern "C" __declspec(dllexport)   // 导出给 Runner 按名字调用

// Test.cpp —— 每个测试项都是一个 USER_CODE 函数，无 main()
USER_CODE void XXX_T(void) {
    TEST_BEGIN
        // 变量定义 → 硬件选择 → 信号连接 → 参数设置 → 参数测量 → 复位
        ...
        binObj.CheckResultAndBin(site, results, count);   // 判限分 Bin
    TEST_ERROR
        binObj.HandlerException(0);                       // 统一异常处理
    TEST_END
}

USER_CODE void SetPassBin(void) { binObj.SetBin(1); }      // 全通过后置 Pass Bin
```

### 4.2 七条通用配方

| # | 套路 | 具体做法 |
|---|---|---|
| 1 | **无 main()** | 靠 `USER_CODE` 导出 + `.tmf` 的 `FuncName` 调度 |
| 2 | **三段式宏** | 统一 `TEST_BEGIN / TEST_ERROR(binObj.HandlerException(0)) / TEST_END` |
| 3 | **电源辅助函数** | 每个工程都有 `POWER_ON` / `POWER_OFF` 或 `PowerOnVdd` / `SetLevel` / `PowerOff`；DPS 惯用 `CurrRange(0.5)` + `CurrClamp(0.5, -0.5)` |
| 4 | **开短路固定配方** | 电源 0 V → PPMU 对全部 I/O 用 **FIMV** 灌/抽 **±100 µA**（ADC0832 为 ±200 µA）→ `VoltClamp(2, -2)` → 判 −1.2 ~ −0.2 V 与 0.2 ~ 1.2 V |
| 5 | **小电流"两段式"测法** | **先大量程稳定，再切小量程精测**（2 µA / 5 µA / 10 µA / 1 µA） |
| 6 | **统一判 Bin** | `binObj.CheckResultAndBin(起始 ParamNumber, 结果向量, 参数个数)`；末尾单独一个 `SetPassBin` 执行 `binObj.SetBin(1)` |
| 7 | **收尾三件套** | 归零 force → `DisConnect` → CBIT `SetOff` + 延时；站点级复位再兜底一次 |

### 4.3 延时量级（工程里的实际取值）

| 场景 | 延时 |
|---|---|
| 单点测量 / 小电流稳定 | 1 ~ 5 ms |
| 上电 / 继电器切换 | 8 ~ 10 ms |
| 大电容 / 低频信号 | 15 ~ 30 ms |

### 5.2 HK24C02（5 项）

OS 测试（VCC 由 PPMU 供 0 V，对 SCL/SDA 加 ±100 µA）→ 漏电流（VCC=5.5 V，测 SCL/SDA 电流 ±1.5 µA）→ **存储功能测试**（写全 0 读全 0 / 写全 1 读全 1 / 写 0x55AA 读 0x55AA）→ standby 电流（100 次软件平均）。

### 5.3 LM358P（5 项）

| 测试项 | 方法要点 | 判据 |
|---|---|---|
| Uos / Ios | DPS ±2.5 V 供电；K1/K2 闭合测 Uo1（Uos），断开测 Uo2（Ios） | Uos 一般 < 1 mV |
| CMRR | V+ 加 +1 V、V− 加 −1 V，测 TP 电压变化 | > 65 dB（手册 Min 65 / Typ 80） |
| Aus（开环增益） | K6 切到 PPMU 供 1 V，测 TP 变化；**TP 电压衰减 1000:1 反馈** | > 80 dB |
| PSRR | 总电源从 5 V 变到 6 V（共模保持不变），测 TP 变化 | > 65 dB（手册 Min 65 / Typ 100） |
| PD（静态功耗） | V+ / V− 分别测 I+ / I− | < 300 µW |

### 5.4 TPS73625（8 项实测 + 1 项关闭）

| 测试项 | 关键条件 | 判据 |
|---|---|---|
| OS | FI = ±100 µA | 0.2 ~ 1.2 V / −1.2 ~ −0.2 V |
| **VOUT** | EN=2V；K3 闭合 250 Ω，VIN = 3/4/5.5 V；K4 闭合 6.25 Ω，VIN = 3/4/5.5 V（共 6 点） | 2.5 V ±1% |
| **ICL**（最大输出电流） | EN=2V，VIN=3.5V，K5 选 3.1 Ω，测 VOUT | Icl = VOUT/3.1 < 800 mA（典型 650 mA） |
| **VDO**（压差） | EN=2V，VIN=2.4V，K4 选 6.25 Ω | VDO = 2.4 − VOUT < 200 mV（典型 75 mV） |
| **IGND**（接地电流） | GND 接 PPMU 强制 0 V 测电流；250 Ω 与 6.25 Ω 两种负载 | Ignd1 < 550 µA（典型 400）；Ignd2 < 1000 µA（典型 800） |
| **LDR**（负载调整率） | FI = −1 mA 测 VOUT1；FI = −10 mA 测 VOUT2；K5 选 6.25 Ω（Imax=400 mA）测 VOUT3 | 典型 0.002 %/mA 与 0.005 %/mA |
| **LNR**（线性调整率） | 250 Ω 负载，VIN = 3 V 与 5.5 V 两点 | ≈ 0.01 %/V |
| PSRR（**LoopCount=0，默认不执行**） | AWG 在 VIN 上叠加交流，DGT 采集输出 | PSRR = 20·lg(VinAC / VoutAC)，关注 100 Hz ~ 10 kHz |

### 5.5 HK32F031F4P6（13 项）

OS（OSP/OSN）→ VOHT → VOLT → VOPUT → VOPDT → NFLT → HSE_OSCT2 → LSE_OSCT2 → PVDT → BIST → HSIT → LSIT → PLLT

关键特点：**大部分测试项需要先输入 PassCode 把芯片切进专门的测试模式**，再运行 Pattern 观察输出。详见 [5.5](5.5-HK32F031F4P6-MCU.md)。

### 5.6 ADC0832（3 项）

| 测试项 | 内容 |
|---|---|
| `OSN_TEST` | 所有 PIN（GND 除外）对地二极管电压 |
| `ADC_STATIC_TEST` | AWG 发 **0~5 V 斜坡（40 Hz）** → 采集 DO → 计算**偏移误差、增益误差、缺失编码、DNL、INL** |
| `ADC_DYNAMIC_TEST` | AWG 发 **5 Vp-p、偏置 2.5 V、1 kHz 正弦** → 采集 DO → FFT → 计算 **SNR、THD、SINAD、SFDR、ENOB**（ENOB = (SINAD − 1.76)/6.02） |

## 六、发现的三处"配置与代码不一致"（学习时要注意）

在整理 6 个工程源码时发现以下问题，**这些是真实的工程 bug 或口径差异**，值得作为"代码审查"练习：

| 工程 | 问题 | 影响 |
|---|---|---|
| **ADC0832** | `.tmf` 声明了 6 个静态参数（含 `ADC_OUT_Lin`），但 `Test.cpp` 只判前 5 个 | 最后一个参数永远不判限 |
| **TPS73625** | `VDO_TEST` 用 (2.4 − VOUT) 的 **V 量级**去比 **0~200 mV** 的限值，量纲不匹配；`LDR_TEST` 第 455 行**漏写 `.Execute()`** | 判限可能永远 Pass；LDR 计算可能不生效 |
| **HK32F031F4P6** | `OSN_TEST` 里 `Connect` 用 `LVLPINS_GRP` 而 `FIMV` 用 `OSPINS_GRP`（两组恰好同成员）；`PLL_TEST` 在 `bhold=false` 时会用**空结果向量**判 bin | 暂时无害，但属于隐患 |

### 6.2 ⚠️ 课件限值 vs 工程 `.tmf` 限值 —— 多处不一致（重要）

整理时把**课件测试计划表**与**工程 `.tmf` 实际限值**逐项对照，发现**多处不一致**：

| 案例 | 参数 | 课件里的限值 | 工程 `.tmf` 实际限值 | 说明 |
|---|---|---|---|---|
| **CD4511** | OSP / OSN | **0.2 ~ 0.8 V** / **−0.8 ~ −0.2 V** | **0.2 ~ 1.2 V** / **−1.2 ~ −0.2 V** | 课件给的是更紧的理论值 |
| **CD4511** | VOH | **4 ~ 6 V** | **3.9 ~ 5 V** | 上下限都不同 |
| **CD4511** | IIL / IIH | **±1 µA** | **±0.1 µA** | 差 10 倍 |
| **CD4511** | VOL | 0 ~ 0.3 V | 0 ~ 0.3 V | ✅ 一致 |
| **TPS73625** | OS | **−1.2 ~ −0.3 V** | **−1.2 ~ −0.2 V** | 下限不同 |
| **TPS73625** | VOUT | **2.475 ~ 2.525 V** | 2.5 V ±1% = **2.475 ~ 2.525 V** | ✅ 一致 |
| **TPS73625** | PSRR | 测试计划表中**未列出** | 工程里有 `PSRR_TEST`，但 **`LoopCount = 0` 默认不执行** | 两边都"没在跑" |
| **HK32F031F4P6** | OS | ±1.2 V / 0.2 ~ 1.2 V | 同 | ✅ 一致 |
| **ADC0832** | **ENOB** | **12 ~ 16 bit** | **7 ~ 8 bit** | ❗ **课件是错的**（见下） |

**其中最值得警惕的是 ADC0832 的 ENOB**：

> ADC0832 是 **8 位** ADC，`ENOB = (SINAD − 1.76) / 6.02`。即使 SINAD 达到理想的 49.9 dB，ENOB 也只有 **8 bit**。所以课件写的 **12 ~ 16 bit 在物理上不可能** —— 这一栏很可能是**从 12/16 位 ADC 的模板里直接沿用、没有改**。工程 `.tmf` 的 **7 ~ 8 bit** 才是对的。

**遇到这类不一致时的处理原则**：

| 情况 | 做法 |
|---|---|
| 课件与工程限值不同 | **以工程 `.tmf` 为准**（工程限值通常由实测统计确定），但要知道课件讲的是手册理论值 |
| 课件数值物理上不可能 | **相信物理，怀疑课件**（如 ENOB 12~16 bit）—— 这是课件模板复用的典型错误 |
| 课件内部自相矛盾 | 找**第三种资料**仲裁（数据手册 / 工程文件 / 实物） |

> 📌 **学习价值**：这一节本身就是最好的"**不要盲信单一资料**"的教材。详细转录见 [5.8 案例课件图表补充](5.8-案例课件图表补充.md)。
