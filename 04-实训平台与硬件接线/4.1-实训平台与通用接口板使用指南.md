## 1. ST2500 从零上手完整流程（简明教程精读）

### 1.1 认识设备与面板

| 部位 | 说明（手册原文） |
|---|---|
| ST2500 测试机 | 机头，面板含**急停按钮、开/关机按钮、状态指示灯、DUT 线缆接口** |
| ST2500 工控机 | 运行 ST-IDE 软件的电脑主机；另配显示器 |

### 1.2 开机（步骤化清单）

1. **Step 1 上电**：测试机头、电脑主机、显示器上电。
2. **Step 2 测试机开机**：按测试机头上的开/关机按钮。
3. **Step 3 工控机开机**：按工控机开/关机按钮；手册注明 **Step2 与 Step3 顺序没有要求**。
4. **Step 4 打开 ST-IDE 软件**：**必须在测试机启动之后**打开；**测试机一旦重启，软件必须跟着重启一次**。

> ⚠️ 顺序口径差异（重要坑）：《简明使用教程》说测试机与工控机开机「顺序没要求」，而《半导体测试实训平台使用手册》的注意事项明确写 **「开机顺序必须先启动控制主机，然后再启动测试机头」**。教学场景按后者执行更稳。
> 实训平台手册补充：控制主机面板标记 1 = **开机按钮**，标记 2 = **重启按钮**；测试机头另有电源按钮（红色标记处）。

### 1.3 登录与模式选择

1. 启动 ST-IDE 集成开发环境，输入账号密码 **dev / dev**，点击 **Login**。
2. 进入模式选择界面，点击 **Development** 进入开发者模式。

### 1.4 新建工程

1. 菜单栏 `File -> New -> Project`。
2. 给工程命名：**必须以英文字母开头**，保存在默认路径。
3. 新建成功后可在左侧工程目录树查看。
4. 新工程默认保存路径：**`D:\MINI-ATE\workspace`**。

**工程文件说明（原表保留）**

| # | 文件 | 含义 |
|---|---|---|
| 0 | CD4015 | 工程文件名（示例工程） |
| 1 | `*.grp` | Group 组文件，定义信号（引脚）组 |
| 2 | `*.job` | Job 工程文件，查看工程信息 |
| 3 | `*.pat` | Pattern 向量文件，定义测试向量文件 |
| 4 | `*.res` | Resource 资源文件，查看测试机连接状态及资源 |
| 5 | `*.sig` | Signal 信号文件，定义信号（引脚） |
| 6 | `*.tim` | Timing 时序文件，定义时序 |
| 7 | `*.tmf` | Test main Function 测试函数文件，定义测试项目（函数）、Limits、Bin 等 |
| 8 | Makefile | 软件自动生成，无需改写 |

### 1.5 导入已有工程

1. 把待导入的工程文件夹放到 **`D:\MINI-ATE\workspace`**。
2. ST-IDE 中 `File -> Import`。
3. 弹窗中点 **Browse**，按上一步路径选中工程文件夹，点 **Finish**。
4. 导入成功后左侧工程目录树可见。
5. ⚠️ **更改了原工程的文件夹名称或文件名，将导致软件识别不到工程文件**。

### 1.6 开发前自检：查看测试机连接状态

打开 `*.res` 文件 → 鼠标左键点击 **Get Resource** → **只有显示资源 Online（在线）才能正常使用测试机**。这是软件侧唯一的权威自检判据。

### 1.7 测试开发流程（十一节，逐项落地）

以 CD4015 引脚开路/短路（OS）测试为例。**信号定义 = 建立 DUT 引脚与测试机资源通道的映射关系。**

#### （一）信号定义 `*.sig`

1. 打开 `*.sig`，添加 1 个测试工位：点击 **Add Site**。
2. 点击 **New Signal** 添加 **15 个**信号；**芯片 GND 不建信号**，可直接连接 Load board 的 **AGND**。
3. 填写「芯片引脚 ↔ 测试通道」映射表，各列含义：

| 列名 | 含义与取值 |
|---|---|
| SigName | 芯片引脚名称，可自行命名 |
| AFEType | 测试机内部资源类，下拉选择：**DPS**（器件供电）、**DIO**（数字 I/O）、**BPMU**（板载精密测量单元） |
| ChType | 通道类型，下拉选择：**Supply**（电源）、**In**（IO 输入）、**Out**（IO 输出）、**Inout**（IO 输入输出）、**Default**（缺省值） |
| Site0_CH | 通道资源硬件地址，格式 `1:1:0`，前两个「1」为默认，「0」为 AFEType 资源通道地址 |

4. 示例：给芯片 VDD 供 +5V → AFEType = **DPS**，ChType = **Supply**，Site0_CH = **1:1:0**（即用测试机 **DPS 的 0 通道**给 VDD 供电）。
5. ⚠️ 所有字符输入必须在**英文输入法**状态下完成；填写完毕**必须点击 Save**。

#### （二）信号分组 `*.grp`（可省）

点击 **New SigGroup**，GrpName 例如 **IOPINS** → **EditSignal** → 选择分组类型（**Select AFEType**，本例 DIO）→ 勾选进组信号（可用 **Add/Delete All Signal** 全选/全删）→ **Save**。
⚠️ **只有同一类型的信号才能放进一个分组**；不知道分组用途时不必强行分组。

#### （三）测试函数定义 `*.tmf`

打开 `*.tmf` → **New Test Function**，命名如 **OSTestFunc**。列含义：

| 列 | 说明 |
|---|---|
| Test Function | 测试函数名称，可按测试项目自行命名 |
| Param ID | 测试函数绝对坐标 ID，自动生成 |
| Param Name | 测试引脚名称，按组添加子项时自动填入 `*.sig` 中定义的信号名（仅注释意义，不填也无影响） |
| Min / Max / Unit | 测试参数阈值与单位，按测试项目自行设置 |
| Sbin / Hbin / Results | Sbin 为软件 BIN，Hbin 为硬件 BIN（BIN 即「分类」）；Results 选 **Fail** 表示结果超出 Min/Max 时按 Sbin/Hbin 分 BIN |

- 帮助文档路径：`ST-IDE -> 菜单栏 -> Help > Document -> ST2500 -> BinDef_Module -> CheckResultAndBin`。
- 添加引脚：在 `OSTestFunc` 列**鼠标右键** → **New Sub Test Group**（按信号组）或 **New Sub Test**（单独）。按组添加时：**Insert Mode** = Cover（覆盖当前行）/ Before（当前行之前）/ After（当前行之后）；**Group** 选 `*.grp` 中定义的 IOPINS；**Prefix/Suffix** 例如给每个信号加前缀 **OS**；Min/Max/Unit 设定本项阈值；点 **OK**。
- 添加 **setPassBin**（右键 → New setPassBin）：全部通过后整体分 BIN，通常 **Sbin = Hbin = 1**，即所谓「一键 BIN 1」。
- Number 列数字前的 **▶** 可折叠/展开测试子项。
- 测试前配置：**LoopCount**（循环测试次数，默认 1，即点 1 次 Run 只执行 1 次）；**DoAll**（默认**不勾选**——前一个测试项出错即终止测试并分 BIN，后续测试项不执行；勾选后每项至少执行 1 次）。

#### （四）时序定义 `*.tim`（不做逻辑功能测试可不配）

打开 `*.tim` → **Add Timing**。

| 列/项 | 说明 |
|---|---|
| TimingName | 时序名称，自行命名，在 Pattern 文件中使用 |
| Period | 时序周期，参考芯片数据手册设置，**不能超过芯片工作的最高频率** |
| Signal | 信号名（`*.sig` 中定义的信号或 `*.grp` 中的信号组），双击下拉选择 |
| WFC | 波形格式符号列，可自行命名（有约定俗成符号） |
| Edge0~4 | 波形事件，测试机内部定义的事件，下拉选择 |
| Time0~4 | 事件（Edge）发生的时刻点，在周期 T 内自行设置 |

**波形符号约定（原表保留）**

| 符号 | 含义 |
|---|---|
| `0` | 在周期 T 内一直提供低电平 |
| `1` | 在周期 T 内一直提供高电平 |
| `.` | 前一个变化电平的延续 |
| `l` | 期望在该时刻采集到低电平（输出） |
| `h` | 期望在该时刻采集到高电平（输出） |

**Edge 事件符号（原表保留）**：**U** 输出高电平、**D** 输出低电平、**Z** 高阻输出（U/D/Z 对应 DUT 输入信号）；**H** 采集高电平、**L** 采集低电平、**X** 不关心采集的电平（H/L/X 对应 DUT 输出信号）。
示例：周期 **1000 ns**，时刻点 **0 ns、500 ns、800 ns、1000 ns**。

#### （五）向量定义 `*.pat`（需配合 `*.tim`）

1. **前提**：先保存所有已编辑文件 → **编译** → **加载**工程。
2. 加载成功后工具栏点 **Pat** 图标 → **New Pattern**。
3. 在 Pat 界面 `File -> Save As…`，保存到工程目录 **`D:\MINI-ATE\workspace\Pattern`**，自行命名后关闭 Pat 界面。
4. 打开 `*.pat` → **Add Pattern**：**Pattern Set Name**（向量名称，在 `*.cpp` 中使用）、**State**（Unload 未加载 / load 已加载）、**Pattern Address**（双击选择创建好的 Pat 文件）、**Start Address**（加载到内存后的起始地址）、**Size**（加载到内存后的大小）。
5. 打开 pat 编辑工具：在 `.\pattern\funcpat.csv` 处右键 → **Open Pattern Tool**。
6. 添加信号：在 comment 列右键 → **Add Column** → 选择需要添加的信号，重复即可。
7. 添加时序名：**Label**（当前 Pattern 行标号，可不填）、**WFT**（填 `*.tim` 中 TimingName 列定义的名称）、**Sequence**（微指令：**nop** = 顺序执行，**stop** = 最后一行以 stop 结束）、**Loops**（重复执行状态，自动生成）、**comment**（注释，可不填）。
8. 按 **CD4015 真值表**填写时序符号。
9. 查看波形：Pat 工具工具栏 **Wave Tools** → 双击信号显示波形。

#### （六）测试程序编写 `Test.cpp`

1. 打开 `Test.cpp`，在 **Outline** 栏点击已定义测试函数可快速跳转。
2. 菜单栏 `Help -> Document` 打开 API 编程手册，查看各资源类示例。
3. 本质：软件下发指令给测试机，内部资源给 DUT 提供电压/电流，再测量电压/电流 —— 即**直流（DC）参数测量**。

#### （七）～（十一）编译 / 加载 / Log / 运行 / 卸载

| 步骤 | 操作 | 快捷键/界面 |
|---|---|---|
| 编译 | 先 **Ctrl+S** 保存；工程树选中工程 → 工具栏**小锤子**，或工程名右键 **Build Project**；控制台显示 **0 错误 0 警告** 即成功 | **Ctrl+B** |
| 加载 | 菜单栏 `Project -> Load`，或工程名右键 **Load**；成功后工程名右侧出现 **Loaded**，工具栏部分图标高亮 | **Ctrl+L** |
| 打开 Log | 点**记事本图标** → 选 **Test log** 显示格式；点**齿轮图标**可配置显示测试细节（可选，不观察 Pattern 细节可不设） | — |
| 运行 | 点工具栏 **▶**（未用到 pattern 时弹出的 Tip 直接 OK）；Log 窗口右上角**橡皮擦**图标清屏 | **Ctrl+R** |
| 卸载 | ① `*.tim` 点 **Unload** 卸载时序 → ② `*.pat` 点 **Unload** 卸载向量 → ③ 工程树选中工程 `Project -> Unload` 或右键 **Unload** | **Ctrl+U** |

⚠️ 测试过程中若修改了时序和向量文件，**必须先按 ①② 卸载，再重新加载**，且**加载之前先保存文件**。

### 1.8 常见坑清单（简明教程内显性/隐性约束汇总）

| # | 坑 | 规避 |
|---|---|---|
| 1 | 先开软件后开测试机 | 软件必须在测试机启动之后打开 |
| 2 | 测试机重启后没重启软件 | 测试机重启 → 软件必须重启一次 |
| 3 | 工程名以数字/中文开头 | 工程名必须以英文字母开头 |
| 4 | 改了工程文件夹名/文件名 | 改名后软件识别不到，恢复原名或重新导入 |
| 5 | 导入工程没放到 `D:\MINI-ATE\workspace` | 必须先放入该路径再 `File -> Import` |
| 6 | 中文/全角字符写进信号、时序表 | 所有字符输入用英文输入法 |
| 7 | 编辑完忘记 Save | 各文件（Sig/Grp/Tmf/Tim）改完都 Save；编译前 Ctrl+S |
| 8 | 没编译、没加载就建 Pattern | `*.pat` 创建前提是保存 + 编译 + 加载成功 |
| 9 | 改时序/向量后直接重载 | 先 Unload 时序、Unload 向量 → Save → Load |
| 10 | 分组混装资源类型 | 同一分组只能放同一 AFEType 的信号 |
| 11 | 未勾选 DoAll 导致后续测试项不执行 | 需要全项都跑时勾选 DoAll |
| 12 | GND 也建信号占通道 | GND 不建信号，直接接 Load board **AGND** |
| 13 | 换 DUT 不卸载工程 | 结束当前 DUT 测试后先卸载工程（Ctrl+U） |

## 2. 半导体测试实训平台（SE-B100 / ST2500 系统）

### 2.1 平台物理结构与资源概览

- 实训平台为**模块化结构**：每个测试模块都带**独立的外围电路**和**测试线缆插槽**，通过测试线缆**直接连接测试机**。
- 各测试模块均**预留调试接口**，便于后续测试时抓取波形或测量芯片引脚电压。
- 模块通用竖向布局：**上部 = 测试线缆插槽 → 中部 = 继电器（数量随模块不同）→ 下部 = 夹持测试芯片的 Socket**。
- Socket 一侧/两侧为调试接口引脚。

| 实训模块（DUT） | 器件类别 | 使用的测试机资源（手册原文） |
|---|---|---|
| ADC0832CCN/NOP8（正文亦作 ADC0832CCN/NOPB） | 模数转换芯片 | DIO、AWG、DPS |
| HK24C02-USG-T（HK24C02） | EEPROM 存储芯片 | **DIO、CBIT** |
| HK32F031F4P6 | MCU 芯片 | **DIO、TMU、DPS** |
| TPS73625DCOR（正文亦作 TPS73625DCQR） | 电源管理芯片，可测 PSRR、LNR | **AWG、DGT、DPS、BPMU、CBIT** |
| LM358P | 运算放大器 | **AWG、DIO、CBIT、DPS** |

### 2.2 与测试机的连接方式

1. 按 2.5 节顺序开机（先控制主机、后测试机头）。
2. 把待测芯片放入对应实训平台的 **Socket** 中。
3. 用**测试线缆**连接：**一端接实训平台（手册图中右侧），另一端接测试机（图中左侧）**。
4. ⚠️ **两边缺口一定要对齐后才可插入；切记不可蛮力插拔。**
5. 点击桌面图标启动测试软件，开始编程测试。

简明教程另说明：**JP1 接口连接测试机，J1 接口通过杜邦线可把测试资源引入到芯片引脚**。

### 2.4 各模块逐款说明（引脚对照 / 继电器 / 调试接口）

### 3.4 CD4511 案例的手工接线方法（跨文件核对结果）

**可核实的引脚事实（CD4511，16 脚）**——课件《测试案例-数字译码器（CD4511）》给出的引脚表：

| Pins | Pinname | Type | Mainfunction |
|---|---|---|---|
| 1 | A0 | I | 二进制数据输入端 A0 |
| 2 | A1 | I | 二进制数据输入端 A1 |
| 3 | A2 | I | 二进制数据输入端 A2 |
| 4 | A3 | I | 二进制数据输入端 A3 |
| 5 | LE | I | 数据锁定控制端 |
| 6 | BI | I | 输出消隐控制信号 |
| 7 | LT | I | 灯测试控制端 |
| 8 | VSS | S | 接地 |
| 9 | VDD | S | 电源正信号 |
| 10 | a | O | 译码输出端 a |
| 11 | b | O | 译码输出端 b |
| 12 | c | O | 译码输出端 c |
| 13 | d | O | 译码输出端 d |
| 14 | e | O | 译码输出端 e |
| 15 | f | O | 译码输出端 f |
| 16 | g | O | 译码输出端 g |

- 器件性质：CD4511 是 **CMOS BCD—锁存/7 段译码/驱动器**，用于驱动**共阴极 LED 数码管**，具备 BCD 转换、消隐和锁存控制、七段译码及驱动功能。
- 控制说明（课件原文）：**BI = 0** 时不论其它输入如何，七段数码管均熄灭（消隐）；**BI = 1 且 LT = 0** 时译码输出全为 1（七段均发亮，显示「8」），主要用来检测数码管是否损坏；**LE = 0** 允许译码输出，**LE = 1** 时译码器处于锁定保持状态，输出保持 LE = 0 时的数值；**a~g 输出高电平 1 有效**。
- ⚠️ **课件内部不一致（提取文本层面）**：管脚说明文字写「BI：4 脚」「LT：3 脚」，而同文件的引脚表写 3 = A2、4 = A3、6 = BI、7 = LT。两处必有其一为课件笔误或对应不同封装/版本。**实际接线必须以器件实物丝印/原厂数据手册为准**，不要按文字描述硬接。CD4511BE 数据手册已抽取为文本，但其引脚功能表为图片，文本中无有效引脚定义可交叉验证。

**手工接线方法（通用可执行步骤，基于 32 针插槽表 + CD4511 功能）**
1. **先定电源域**：VDD(9) 由 **DPS 通道**（如 DPS_SENSE/FORCE_CH0，PIN 29/32 区）供电，或直接用板端 **`5V_DUT`（PIN 6）**；VSS(8) 接 **GND（PIN 7）**，模拟部分参考接 **AGND**。
2. **输入脚接线**：A0～A3(1~4) 接 **DIO 通道**（CH0～CH31 中任选，用杜邦线从插槽 a 列引出，**避免误用 `_HV` 通道**）。
3. **控制脚接线**：LE(5)、BI(6)、LT(7) 分别接 **DIO 通道**；注意上电默认电平——若悬空可能因 CMOS 高阻导致乱码，应先明确每个控制脚的静态电平要求再上电。
4. **输出脚接线**：a～g(10~16) 接 **DIO 通道** 用于 VOH/VOL 测量；若外接共阴极数码管，需串**限流电阻**，并把数码管公共端接 GND（不是 AGND 与 DIO 混用）。
5. **核对通道映射表**：把「芯片引脚名 ↔ AFEType（DIO/DPS）↔ ChType（In/Out/Inout/Supply）↔ Site0_CH」逐行填入 `*.sig`，`Site0_CH` 形如 `1:1:n`，n 为资源通道号（做法同 1.7 节（一））。
6. **OS 测试**：课件给出的条件为 **FI = ±100 µA 加流后测电压**，Limit：FI = +100 µA 时 VOUTmin = 0.2 V、VOUTmax = 0.8 V；FI = −100 µA 时 VOUTmin = −0.8 V、VOUTmax = −0.2 V。对**所有有上下保护二极管的引脚**做 OS 测试。
7. **VOH 测试**：以 **VDDmin** 作为器件 VDD 电压，用向量使输出全部置「1」，待稳定后用测试机 **PPMU** 测量输出脚电压是否满足数据手册 VOH 要求。

> 📌 说明：课件中的《CD4511 测试 DUT 板原理图》《VOH 测试步骤》《数据手册标准参数》等页在提取文本中**仅有标题、内容为图片**，因此**「引脚→测试机通道」的官方对应表无法从现有文本恢复**。上表与步骤中的通道选择属于**按 32 针插槽定义给出的可执行方法**，不是手册原表；若需与教程/考核答案完全一致，请对照原 PDF 的原理图页。

### 3.5 接线检查方法与易错点

**接线检查方法（逐条可执行）**
1. **目视 + 通断检查**：对照 2.3 节 32 针表，用万用表逐针确认「插槽针位 ↔ 万用板元件脚」的连通，重点核对 AGND/GND、DPS FORCE/SENSE 是否成对使用。
2. **电源先行**：先只连电源与地，上电后在调试接口测 VDD/VCC 电压（如 5 V、1.8~5.5 V），确认后再连信号线。
3. **软件侧确认**：`*.res` → **Get Resource** 必须 **Online**；先跑 OS 测试，全脚 OS 通过后再做功能/参数测试。
4. **换片断电**：更换芯片必须停止测试、断电，**不可带电更换芯片**。
5. **插拔手法**：96Pin 端口/线缆**缺口对齐后才插入**，禁止蛮力插拔。

**易错点清单（板端特有；软件侧坑见 1.8）**

| # | 易错点 | 后果/规避 |
|---|---|---|
| 1 | I2C（HK24C02）SDA/SCL 未上拉 | 读写失败；搭上拉电阻（平台侧为 RL14/CBIT0） |
| 2 | AGND 与 GND 混接 | 基准错乱；AGND 在 PIN 2/5/12/17/23/28，GND 在 PIN 7 |
| 3 | 误用 `_HV` 通道（CH0/CH8/CH16/CH24）或误接 `-7.2V_DUT`、`11.5V_DUT` | 超压损伤低压 DUT；先查通道属性再连线 |
| 4 | DPS 只接 FORCE 未接 SENSE | 压降导致测量偏差；按开尔文成对使用 |
| 5 | 继电器（CBIT）状态与程序不一致 | 资源未导通（LM358P 的 RL25/RL21/RL22、ADC0832 的 RL1/RL2/RL3、TPS73625 的 RL4/RL6/RL8）；先置 CBIT 再测量 |
| 6 | 芯片 1 脚未对白三角 | 引脚全错位；装片必查 |
