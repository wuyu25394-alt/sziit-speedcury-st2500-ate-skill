## 顺序为什么重要

同一批测试项，换个顺序，测出来的结论会不一样。课件给过一张量产流程，可以照抄来看：

**Bin10 开始 → 连续性 → 开短路（Fail → Bin 9）→ 粗测 IDD（Fail → Bin 8）→ 粗测功能（Fail → Bin 5）→ 功能 VIL/VIH（Fail → Bin 7）→ 100 MHz 功能（Pass → Bin 1）→ 75 MHz 功能（Pass → Bin 2）→ 静态 IDD（Fail → Bin 6）→ 动态 IDD（Fail → Bin 5）→ 漏电流 → 输出电平（Bin 4）**

顺序不是随便排的，背后三条原则：**最便宜的先做**（开短路几十微秒，跑功能要加载向量、等时序，单颗时间高一个量级）；**测「接触」的先做**（接触不良时后面每一项的数都不可信）；**分档的往后放**（100 MHz 过不了再测 75 MHz，把「能用但慢」的片子分到低档 Bin，而不是直接报废）。

> [!TIP]
> **🔧 Know-how｜自己排流程时的顺序口诀**
>
> - **情境**：接手一颗新芯片，几十个测试项要定先后。
> - **做法**：接触 → 功耗 → 功能 → 分档 → 参数；前一步不过就不必进下一步。
> - **为什么**：每一步都在排除一类原因，顺序对了，失败信息才指向明确。
> - **没做会怎样**：先测参数后测接触，一个脏 Socket 能让整批数据看起来「参数全飘」。
> - **相关章节**：[第 19 章 调试与排错：连不上、不生效、对不上](../../5-programming/19-debugging/README.md)

## 一个测试项的成分

一个测试项由五样东西组成：**编号、名字、条件、判据、Bin**。软件里对应 `.tmf` 的一行：

| 字段 | 在 `.tmf` 里 | 含义 |
|---|---|---|
| 编号 | Number / Param ID | 自动生成，子项从 0 开始 |
| 名字 | Test Function / ParamName | 代码里按名字取结果 |
| 判据 | Min / Max / Unit | 结果落在区间内即通过 |
| Bin | Sbin / Hbin / Results | Results 选 Fail，超限就按这两个 Bin 分 |
| 条件 | 不在这里 | 写在 `Test.cpp` 的测试函数里 |

最后一行最容易被忽略：**`.tmf` 里只有判据，条件在代码里。** 同一份 `.tmf` 贴到另一个工程，判据还在，条件没了，测出来的数完全不是一回事。

再看一份真实的测试计划（课件里一颗 BGA256 封装的可编程逻辑器件，计划代号 ECP5-25）：

| Test Name | Vcc | Force / Expect | Pinlist | Timing |
|---|---|---|---|---|
| opens | 0 V | Force −200 µA，Pass if > −900 mV | ALL_PINS | — |
| shorts | 0 V | Force −200 µA，Pass if < −200 mV | ALL_PINS | — |
| icc_core | 1.155 V | Pass if < 344 mA | Vcc | 100 ns |

三行读出三件事。第一，`opens` 与 `shorts` 是同一组引脚、同一个电流，只有判据方向相反——灌 −200 µA 后，电压太负说明开路，太接近 0 说明短路，两条合起来才围出一个正常窗口。第二，`icc_core` 的 1.155 V 和 100 ns 都是条件，不是判据。第三，`ALL_PINS`、`Vcc` 是引脚集合的名字，不是某一根引脚。

> [!NOTE]
> **📖 名词｜测试计划（Test Plan）**
>
> - **定义**：把「测哪些项、什么条件、判据多少、什么顺序」写下来的文档，是程序和芯片之间的合同。
> - **现场用法**：「计划里没这一项，你凭什么加进去？」
> - **相关名词**：数据手册、测试程序、Test Flow、Bin
> - **常见混淆**：和测试程序混为一谈。计划是人看的表，程序是机器跑的代码，两者会不一致。

## Bin：把「坏」分出原因

测完一颗芯片，结果不能只有「好」和「坏」两种。分档（Bin）分两层：

| | Sbin（软 Bin） | Hbin（硬 Bin） |
|---|---|---|
| 给谁看 | 工程师 | 分选机 |
| 粒度 | 细，一项一个号 | 粗，几个号够用 |
| 例子 | 开短路失败记 2 | 落进 3 号料管 |

一条测试项如果 `Results = Fail`、`Sbin = 2`、`Hbin = 3`，意思就是：这颗在开短路这项超限，软件记成 2-3。工程师从 Sbin 知道坏在哪一项，分选机从 Hbin 知道往哪个管里放。

为什么要分开？分选机的料管数量有限，Hbin 只能是几个；而失效原因有几十种，Sbin 装得下。把「给人看的原因」和「给机器看的去处」拆开，才能在不改硬件的前提下把失效分细。

两个特殊项：`SetPassBin` 只能有一个，一般放在最后，Sbin 与 Hbin 都置 1，表示全部通过；`SetErrorBin` 是兜底，程序逻辑漏了的时候用它分档，必须指定两个 Bin。

> [!NOTE]
> **📖 名词｜分档（Bin）**
>
> - **定义**：按测试结果给芯片分类的编号，软 Bin 记原因，硬 Bin 定去处。
> - **现场用法**：「这批 2 号 Bin 特别多，查一下开短路。」
> - **相关名词**：Sbin、Hbin、Pass/Fail、良率
> - **常见混淆**：把 Bin 号当成测试项编号。Bin 是结果的分类，测试项是过程的一步。

## 重测与重试：什么时候允许，什么时候是危险信号

**重测**是同一颗芯片、同一工位再跑一遍；**重试**是换工位或换机台再测。

允许重测的场合很具体：第一次失败落在开短路或连续性项；同一个 Socket 连续几颗都在同一项失败；刚换过探针卡、DUT 板或线缆——共同点是失败更像是接触，不是芯片。

危险信号同样具体：某一项的重测通过率明显高于其他项。那说明判据压在分布边界上，或者测量本身不稳（延时不够、接触电阻大）。这时候把重测当解决办法，等于把边界品放进合格品。

软件里有两个开关，作用完全不同：**StopOnFail** 勾选后一颗失败就停，省时间，适合筛片；**DoAll** 勾选后失败也继续跑完这一回合、但不执行分 Bin，费时间，拿的是完整数据。

一句话：**重测是用来区分「芯片坏」和「接触坏」的，不是用来把 Fail 变成 Pass 的。**

## Datalog：每颗芯片留下什么

每测一颗，软件都留一条记录：各测试项的实测值、Pass/Fail、Sbin 与 Hbin、时间；晶圆测试还要带上这颗裸片的坐标。格式支持 txt、csv 与 STDF，软件里分 Table Log 与 Text Log 两种视图。

留它不是为了存档，是为了四件事：

**定限值。** 工程里那些判据（比如开短路 0.2～1.2 V）大多是从实测分布统计出来的，不是抄手册抄来的。没有 Datalog 就没法统计。

**看工艺。** 某个 Bin 的比例突然涨，是最早的产线信号，比成品出货检验早得多。

**回溯。** 客户退回一批，要能查到当时每一颗的实测值，才能判断是批次问题还是个案。

**比对机台。** 两台机器测同一批，比的是分布，不是单颗的数。相关性对不上，先怀疑机台。

> [!TIP]
> **🔧 Know-how｜改判据之前先导一份分布**
>
> - **情境**：判据要调，或者准备换一台机台跑同一个产品。
> - **做法**：先跑一批，把该项的实测值导出，看均值、离散和尾部；改完再跑一批，比两次的分布。
> - **为什么**：只有分布能区分「判据不合适」和「芯片真的变了」。
> - **没做会怎样**：判据改来改去，问题在原地打转，还留下无法解释的良率台阶。

## 本章重点

1. 流程的顺序有讲究：接触类最便宜的先做，功耗次之，功能与分档在后，参数最后。
2. 一个测试项 = 编号 + 名字 + 条件 + 判据 + Bin；`.tmf` 只存判据，条件在 `Test.cpp` 里。
3. 一条限值要连条件一起读。`opens` 与 `shorts` 用同一个电流、相反方向的判据，合起来才围出正常窗口。
4. Sbin 记原因、Hbin 定去处；`SetPassBin` 只能有一个，放最后。
5. 重测用来区分芯片坏与接触坏；Datalog 用来定限值、看工艺、做回溯与机台比对。
