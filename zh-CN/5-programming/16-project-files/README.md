## 为什么要把一件事拆成七份

前面十五章讲的是「测什么、判什么」。到了软件里，这些想法要落成一份工程：七个配置文件，加一份手写的 `Test.cpp`——它连同 `interface.h` 一起，被编成 `Test.dll`。

拆开的理由不是格式好看，是**改动频率不一样**：换引脚分配只动 `.sig`，换时序只动 `.tim`，换判据只动 `.tmf`，代码一次不动。

七份文件不是并列的，是一条依赖链，后一份从前面那份里挑名字：`.res` → `.sig` → `.grp` / `.tim` → `.pat` → `.tmf` → `Test.cpp`。链上的约束是硬的——`.sig` 里没有的名字，`.grp` 里选不到；`.tim` 里没定义的管脚，编 Pattern 时会报错。

> [!NOTE]
> **📖 名词｜测试程序（Test Program）**
>
> - **定义**：一份能被测试机加载并执行的工程，含资源与引脚映射、时序与图形、测试项与限值，以及编译好的测试库。
> - **现场用法**：「这一版程序在 workspace 里，先 Load 一下跑个 Manual Test。」
> - **相关名词**：Job、Test Flow、Test.dll、Pattern
> - **常见混淆**：把「程序」等同于那份 `Test.cpp`。代码只是其中一份，七个配置错一个就跑不起来。

## 逐个说清楚：谁生成、谁编辑、改了影响谁

| 文件 | 谁生成 | 谁编辑 | 改了影响谁 |
|---|---|---|---|
| `.job` | 新建工程时自动生成 | 基本不动，只用来 `Load` / `Unload` | 换机器要改 `AteHomePath` 与 `jobDir` |
| `.res` | 软件启动自检后写入 | 点 `Get Resources` 刷新 | `.sig` 的 `AFEType` 候选与通道上限 |
| `.sig` | 手工建 | 测试工程师 | `.grp`、`.tim`、`.pat`、`.tmf` 与代码里的信号名 |
| `.grp` | 手工建 | 测试工程师 | 代码里能用组名代替逐个引脚 |
| `.tim` | 手工建 | 测试工程师 | Pattern 的 `WFT` 列与每格的 WFC 值 |
| `.pat` | 手工登记 | 测试工程师 | 代码里 `dio.Pattern("名字")` 引用的名字 |
| `.tmf` | 手工建，保存时生成函数骨架 | 测试工程师；限值常由产品工程师定 | 测试顺序、限值、Bin 与代码里的函数名 |

七份里有两对：`.sig` 与 `.grp` 管引脚，`.tim` 与 `.pat` 管激励；`.res` 管机器上有什么，`.tmf` 管测什么、判多少，`.job` 把全部串起来。

> [!TIP]
> **🔧 Know-how｜信号名是整份工程的骨架，一次定好**
>
> - **情境**：新建工程，要为一个 20 脚的芯片分配信号名。
> - **做法**：按数据手册的引脚名起（`VDD`、`PA0`、`NRST`），不按通道号起（别叫 `DIO8`）。
> - **为什么**：这个名字被七份文件反复引用，是它们之间唯一的公共词汇。
> - **没做会怎样**：换接口板重分配通道后，名字与实际全对不上，七份文件要挨着改一遍。
> - **相关章节**：[第 17 章 Test.cpp：用户代码怎么被调用](../17-test-cpp/README.md)

## `.res` 这一步为什么不能跳过

软件启动时做一次硬件自检，把机台里的板卡、模块、通道数写进 `.res`。它是给 `.sig` 的编辑界面当候选名单用的。

五列：`Adapter` 机头（最多 8 个）、`SlotID` 业务板（单机头 5 块）、`Status` 在位状态（`OnLine` / `OffLine`）、`AFEModule` 模块（`AWG`、`DGT`、`RVS`、`DPS`、`BPMU`、`CBIT`、`DIO` 七种）、`Channel` 通道数。

顺序因此是硬的：`.res` 里有这种资源，`.sig` 的 `AFEType` 才选得到。机上没装 SMU20，列表里就不会有 `SMU` 与 `SMU_GANG2`～`SMU_GANG4`（见[第 7 章 SMU](../../2-instrumentation/07-smu/README.md)）。

通道号的上限，由这种资源在一块板上有几个决定：DPS 0～3、DIO 0～31、TMU 0～3、CBIT 0～7，AWG 与 DGT 只有 0。

> [!NOTE]
> **📖 名词｜AFE 类型（AFEType）**
>
> - **定义**：`.sig` 里为每个信号指定的测试机资源种类，决定它由哪种模块驱动或测量。
> - **现场用法**：「这个脚走 DIO8，那个脚走 DPS0，先把 AFEType 对好再往下填。」
> - **相关名词**：ChType、FBID、Channel、Share
> - **常见混淆**：和 `ChType` 混。`AFEType` 选的是**资源种类**，`ChType` 说的是这个信号的**方向**（`Inout`、`Supply`、`In`、`Out`、`DEFAULT`）。

## `.tmf` 的双层结构

`.tmf` 是七份里唯一同时管「流程」和「判据」的，所以多一层。

**上层是 Site 与循环。** `SiteInitName` 与 `SiteResetName` 是每个工位的初始化与复位函数名，不可编辑；`LoopCount` 设循环次数；`StopOnFail` 中途失败就停；`DoAll` 失败也跑完当前回合，但不分 Bin。

**下层是 Func 列表。** 一行一个测试项：编号、函数名（自动生成、不可重复）、`ParamName`、`Min` / `Max`、`Unit`、`Sbin` / `Hbin`、`Results`。每个 Func 下可挂多个子项，真正带限值的是子项那一行；子项编号从 0 起，界面上第一个是 1000，代码里对应 `0`。

限值有两种语义：电参数比较，结果落在 `Min`～`Max` 之间即 Pass；Pattern 比较，图形里已设比较，`Min` 与 `Max` 都填 `1`。

两个系统项不能删。`SetPassBin` 只能有一个，一般排最后；`SetErrorBin` 建 tmf 时自动生成，只填 Bin 号且不能与正常项重号——逻辑有疏漏、跑不到任何 Bin 时它兜底。

> [!NOTE]
> **📖 名词｜软分档与硬分档（Sbin / Hbin）**
>
> - **定义**：`Sbin` 是软件端记录的档位，写进 Datalog；`Hbin` 是测试结束后发给分选机的档位号。
> - **现场用法**：「这项 fail 记 2-3，芯片落到 Handler 的 BIN3。」
> - **相关名词**：Bin、Results、Datalog、Handler
> - **常见混淆**：以为两个号必须一样。可以不一样：软件端要细分失效原因，硬件只有几个料管，就用 Sbin 记细、Hbin 给粗。

> [!TIP]
> **🔧 Know-how｜判据只改 `.tmf`，别去改代码**
>
> - **情境**：试产时某项良率偏低，怀疑限值定得太紧。
> - **做法**：在 `.tmf` 里改对应子项的 `Min` / `Max`，保存，再跑一轮，代码一行不动。
> - **为什么**：判据属于产品要求，不属于测量方法；放在配置里，改判据就不必重编译。
> - **没做会怎样**：把限值写成代码里的常数，数据手册一改判据就得重新 Build 一个 DLL 再验证一遍。
> - **相关章节**：[第 17 章 Test.cpp：用户代码怎么被调用](../17-test-cpp/README.md)

## 一个最小工程的建立顺序

顺序不能乱，每一步都在给下一步提供候选名单。

1. 新建工程：`File → New → Job File`，`.job` 成为树根。
2. `.res`：点 `Get Resources`，确认每块板 `OnLine`，模块与通道数对得上。
3. `.sig`：先 `Add Site` 再 `New Signal`，填 `SigName`、`AFEType`、`ChType` 与 `Adapter : FBID : Channel`。
4. `.grp`：按用途分组（输入、输出、电源），一组之内只放同一种资源。
5. `.tim`：定周期与各信号的 WFC，周期带单位、不超过 256 µs，取 4 的整数倍。
6. `.pat`：登记 Pattern Set Name 与 CSV 路径，源文件放在工程的 `pattern` 文件夹，最后一行必须是 `stop`。
7. `.tmf`：`New Test Function` 逐项建，加子项、填限值与 Sbin/Hbin，确认 `SetPassBin` 与 `SetErrorBin`。
8. `Test.cpp`：保存 `.tmf` 时函数骨架自动生成，在骨架里填测量逻辑。
9. 收尾：`Build` 成功才能 `Load`，一次只能 `Load` 一个工程，改过代码要 `Unload` 再 `Build`。

---

## 本章重点

1. 七个配置文件按**改动频率**拆开：换引脚只动 `.sig`，换时序只动 `.tim`，换判据只动 `.tmf`，代码可以一动不动。
2. 它们构成依赖链 `.res` → `.sig` → `.grp` / `.tim` → `.pat` → `.tmf` → `Test.cpp`，后一份的名字来自前一份。
3. `.res` 是自检结果，决定 `.sig` 里 `AFEType` 能选什么、`Channel` 能填到几，跳过它，后面全是死路。
4. `.tmf` 分两层：Site 与循环在上，Func 列表在下；每个 Func 带自己的 Bin 与一组带限值的子项，子项编号从 0 起。
5. 建立顺序固定：`.res` → `.sig` → `.grp` → `.tim` → `.pat` → `.tmf` → 写代码 → `Build` → `Load`。
