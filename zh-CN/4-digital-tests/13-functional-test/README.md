## 功能测试在测什么

直流参数一项一项量，每项一个数、一个限值。功能测试换个问法：**给一组输入，输出是不是期望的那一组？**

答案只有 Pass 或 Fail。VOL 合格但译码错了——输入 0101，该亮的不亮，这种错误直流参数一个都抓不到。

功能测试覆盖的是逻辑：译码、锁存、计数、移位、状态机、通信协议。它不告诉你余量，只说这一拍对不对。

CD4511 的 FUNC 只有 3 行向量，周期 10 µs。3 行覆盖不了 10 个 BCD 码加 6 个非法码——**覆盖多少由写程序的人决定**。

> [!NOTE]
> **📖 名词｜测试向量与测试图形（Vector / Pattern）**
>
> - **定义**：Pattern 是一组按顺序排列的向量；每行叫一个 Vector，写明这一拍各引脚输入与期望输出。
> - **现场用法**：「这条 Pattern 跑一遍要 200 µs，深度 3 万行。」
> - **相关名词**：向量深度（Vector Depth）、周期（Cycle）、WFT、微指令
> - **常见混淆**：把 Pattern 和 Vector 当两个东西。课程叙述里两者同义；严格说 Pattern 是整个文件，Vector 是其中一行。

## 从真值表到向量

真值表一行一种组合。变成向量就是照抄：输入 0/1，输出高低换成 H/L。

74LS194 的真值表有七行：复位、保持、左移两行、右移两行、并行加载。表里的 `l`、`h` 不是「低 / 高」，是「低 / 高，而且要在时钟沿之前建立」。**这正是真值表里最容易抄漏的东西**——抄成 0/1，向量就跑不出正确时序。

符号：输入用 `0`、`1`、`Z`；输出用 `H`、`L`、`M`（高阻）、`V`（有效）、`X`（不关心）。

**`X` 是输出 mask 态**：写在输入脚上，测试机会把它接到比较器，当成输出处理。

复杂芯片抄不动。Pattern 来自仿真：WGL、STIL 带扫描向量、时序固定，转换简单；VCD 是功能波形，要看 ATE 结构。

## Pattern 文件长什么样：.sig、.grp、.pat

一个能跑的功能测试工程，至少要四样东西：`.sig`、`.grp`、`.tim`、`.pat`。

`.sig` 是根：每行把信号名绑到 `Adapter : FBID : Channel` 三元组——哪个机头、哪块板、第几个通道。`AFEType` 决定 DIO 还是 DPS，`ChType` 决定输入、输出还是双向。

`.grp` 是别名：把数据线打包，代码和时序用组名。一个组里必须是同一种 AFEType。

`.pat` 是目录，只存「`Pattern Set Name` → CSV 路径」。代码里 `dio.Pattern("VOPUPAT")` 的名字就在这里。真正的向量在 `pattern/*.csv`：`Lable`、`WFT`、`Sequence`，后面每根引脚一列，填 WFC 值。

`.tim` 不在 `.pat` 里，但少了它跑不起来：每行向量指定一个 `WFT`，`WFT` 定义周期和每个 WFC 的驱动 / 比较沿。**Pattern 说这一拍做什么，Timing 说在什么时刻做。**

> [!NOTE]
> **📖 名词｜信号映射（.sig）**
>
> - **定义**：把用户自定义的信号名绑定到测试机物理资源通道的配置文件，一行一个信号。
> - **现场用法**：「新板子先改 sig，把 PA4 挪到 DIO0，其他别动。」
> - **相关名词**：AFEType、ChType、Adapter、FBID、Channel
> - **常见混淆**：把 sig 当成芯片引脚表。它描述的是测试机这一侧接在哪，芯片那一侧由 DUT 板决定。

> [!TIP]
> **🔧 Know-how｜先让机器自检，再写 sig**
>
> - **情境**：换了机台、加了板卡，或者第一次打开别人的工程。
> - **做法**：先在 `.res` 里点 `Get Resources` 让机器自检，再去 `.sig` 的 `AFEType` 下拉里选资源。
> - **为什么**：下拉里的选项来自自检结果，机上没装的板卡不会出现。
> - **没做会怎样**：sig 里写了不存在的资源，编译能过，上机找不到通道。
> - **相关章节**：[第 16 章 工程文件：.job、.sig、.grp、.tim 与 .pat](../../5-programming/16-project-files/README.md)

## 边测边判：比较沿在哪一刻

每一拍，测试机做两件事：驱动沿把输入打出去，比较沿把输出读回来。CD4511 的 WFT1 把这两件事分得很开：周期 10 µs，输入 WFC `0` 在 0 µs 驱动低电平、WFC `1` 在 0 µs 驱动高电平；输出的 `L` / `H` / `X` 在 **9 µs** 处比较。开始打输入，快结束才读输出，中间 9 µs 给芯片反应。

这 9 µs 不是随便定的：CD4511 在 5 V 下 tPHL 最大 1040 ns、tPLH 最大 1320 ns，1 µs 出头就翻完。**太早，输出没翻到位；太晚，撞下一拍。**

门限由 PinLevel 定：驱动侧 VIH / VIL，比较侧 VOH / VOL，课件示例是 `SetVih(5.0)`、`SetVil(0.0)`、`SetVoh(3.5)`、`SetVol(0.7)`。VOH 和 VOL 之间是不确定区，比较器卡在中间判高低。

采样有单点（**Edge Strobe**）与窗口（**Window Strobe**）两种。边沿慢、抖动大用窗口，避免刚好采在跳变点上。

> [!NOTE]
> **📖 名词｜采样沿（Strobe）**
>
> - **定义**：一个周期内对输出电平进行采样比较的时刻点；分单点采样（Edge）与窗口采样（Window）。
> - **现场用法**：「把比较沿往后挪 500 ns 再跑一遍，看还 fail 不 fail。」
> - **相关名词**：驱动沿、周期（Cycle）、建立时间、传输延时
> - **常见混淆**：把驱动沿和比较沿混。一个负责把 0/1 打出去，一个负责把结果读回来。

## 失败定位：第几拍、第几个引脚

跑完一条 Pattern，测试机给出哪一行、哪个引脚、读到什么、期望什么。`Test()` 执行，`GetFailResult(Result)` 取回。

一条 fail 记录往三个方向追：

1. **追到向量**。行号对应 CSV 那一行，看输入和期望输出 WFC 有没有写反，最常见是 `H` 和 `L` 抄反。
2. **追到时序**。这一行用的 `WFT` 在 `.tim` 里是什么周期、比较沿在第几纳秒。比较沿太早是最典型的「好片误判」。
3. **追到电平与硬件**。VOL / VOH 是不是比芯片实际输出还严；继电器有没有吸合；插座接触电阻是不是大了。

顺序不能反：先向量，再时序，最后硬件。**前两者改起来一分钟，硬件要拆板子。**

fail 落在输入脚，多半不是芯片的问题，而是向量里写了 `X`。先查符号。

> [!TIP]
> **🔧 Know-how｜输入脚不要给 X**
>
> - **情境**：某一拍里，某个输入脚给 0 给 1 都不影响结果，顺手写了 `X`。
> - **做法**：给它一个确定的 `0` 或 `1`；确实要保持上一拍状态的，用 `P`。
> - **为什么**：`X` 是输出 mask 态，机器会把这个脚切到比较电路，当输出比较。
> - **没做会怎样**：这一拍必然 fail，而且 fail 的引脚看起来毫无道理；更糟的是驱动器和 DUT 可能同时驱动同一个脚。
> - **相关章节**：[第 14 章 时序与电平：Timing、PinLevel 与波形](../14-timing-and-levels/README.md)

> [!TIP]
> **🔧 Know-how｜Pattern 的最后一行必须是 stop**
>
> - **情境**：手写或工具生成的 CSV，末尾停在最后一条向量上。
> - **做法**：在最后加一行 `stop`；要循环跑的段落用 `loop` 或 `repeat` 包起来。
> - **为什么**：`stop` 是结束标志，测试机靠它判断跑完了。
> - **没做会怎样**：轻则报超时，重则 Pattern 一直跑不完，测试卡在那一项上。
> - **相关章节**：[第 16 章 工程文件：.job、.sig、.grp、.tim 与 .pat](../../5-programming/16-project-files/README.md)

## 本章重点

1. 功能测试判的是逻辑对不对，不是数值够不够；结果只有 Pass / Fail，直流参数替代不了它。
2. 真值表一行变一个向量：输入 0/1，期望输出 H/L；`X` 是输出 mask 态，输入脚不能写。
3. 功能测试四件套：`.sig` 定通道、`.grp` 定分组、`.tim` 定波形、`.pat` 指向 CSV 向量。
4. 每一拍先驱动、后比较；比较沿要落在输出稳定窗口内，太早会读到上一拍。
5. fail 先追向量、再追时序、最后查硬件；报错落在输入脚上，多半是写了 `X`。
