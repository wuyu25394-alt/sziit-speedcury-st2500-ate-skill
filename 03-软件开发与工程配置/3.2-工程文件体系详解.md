# ST2500 测试工程文件体系详解

> 字段级说明。逐文件语法与相互引用关系。

## 3. 工程文件体系逐个说明

### 3.1 文件关系总览（P.96 图 2-56）

```
        Sig ──┐                        Tim ──┐
              ├──► Grp（信号组）               ├──► Pat ──► pattern/*.csv
        Res ──┘                        Test.cpp + Tmf（测试项/分BIN）
        job = 工程容器，MakeFile = 编译脚本，interface.h = 头文件
```
> **Sig 和 Grp 用于连接芯片与测试机；Pat 和 Tim 构成芯片的输入；Test.cpp 和 Tmf 编辑芯片测试程序。要运行测试必须构建上述全部文件。**

**JobExplore 树中显示的文件类型**（P.96）：`.job`、`.res`、`.sig`、`.grp`、`.tim`、`.pat`、`.tmf`、`Program Source Files`（`.h`、`.cpp`）、`MakeFile`。

### 3.2 `.job`（Job 项目工程文件）

- 测试工程的**容器/入口**，JobExplore 的树根。新建：`File → New → New Job / Job File`；导入：`File → Import`（拷贝到当前 Workspace）。
- 右键菜单：`Load`、`Unload`、`ReName`、`Refresh`、`Delete`、`Edit`、`Edit in Text Editor`、`Open Containing Folder`。
- **字段级语法：手册未给出 `.job` 的文本格式**（GUI 中只以树形展示，未列出文件内容）。

### 3.3 `.res`（测试机板卡资源文件）

- 关联**机台资源信息与板卡资源定义**。软件启动时做硬件自检，把自检结果（机台资源信息）存入 res 文件，后续用作 **sig 文件编辑的参考依据**（P.100）。
- **字段级结构**（P.101，Preview 表格列）：

| 列 | 含义 |
|---|---|
| `Adapter` | 当前测试机头，最多可配置 **8 机头** |
| `SlotID` | 业务板编号，与硬件一一对应，**单机头 5 块业务卡 Slot1~Slot5** |
| `Status` | 在位状态：`OnLine`（在位）/ `OffLine`（未在位） |
| `AFEModule` | 对应的 AFE 模块：**AWG、DGT、RVS、DPS、BPMU、CBIT、DIO** 共 7 种 |
| `Channel` | 当前 AFE 模块**可用通道数**，通道编号默认从 0 开始 |

- 控件：`Get Resources`（获取当前测试机板卡资源，用自检信息更新业务板卡状态）、`Collapse`（收起/展开资源）。
- **字段级语法（文本格式）：手册未给出**。

### 3.4 `.sig`（芯片引脚资源配置文件）— 字段级

**作用**：定义芯片引脚使用的测试机资源，即"自定义芯片管脚信号名 ↔ 测试机物理资源通道"的映射（P.102）。

| 字段 | 含义 | 可编辑性 |
|---|---|---|
| `SigName` | 信号名（自定义） | 手动输入编辑。**同一 Sig 文件内不可重名**，重名会标红并在保存时弹提示 |
| `AFEType` | AFE 类型 | 下拉选择 |
| `ChType` | 通道类型 | 依 AFE 类型下拉设置 |
| `Adapter` | 操作的机头 | 级联模式下出现 |
| `FBID` | 机头的业务板编号 | **1~5**，对应 5 块业务板卡 |
| `Channel` | 该类型信号使用的通道 | 下拉选择（通道数由 AFEType 决定） |
| `S` 标志 | 表示当前信号 **Share（共享）** 其他信号的通道资源 | 只读标记 |

**`ChType` 取值**：`Inout`（输入输出）、`Supply`（供电）、`In`（输入）、`Out`（输出）、`DEFAULT`（默认）。

**AFEType 与 ChType 对应表（P.105 表 2-22）**

| AFE 类型 | 功能 | ChType |
|---|---|---|
| `CBIT` | 控制继电器，用于切换不同 AFE 资源通道 | `Default` |
| `DPS` | 电源管理（芯片上下电） | `Supply` |
| `DPS_GANG2` | 两通道 DPS Gang | `Supply` |
| `DPS_GANG3` | 三通道 DPS Gang | `Supply` |
| `DPS_GANG4` | 四通道 DPS Gang | `Supply` |
| `DIO` | 数字输入/输出/高精度测量（输入 Pattern） | `Inout/In/Out` |
| `BPMU` | 板载高精度测量 | `Inout/In/Out` |
| `AWG` | 波形发生器 | `In/Out` |
| `DGT` | 数字采集模块 | `In/Out` |
| `RVS` | Reference 电源管理模块 | `Supply` |
| `TMU` | AC 参数测试 | `In/Out` |

**控件**：`Add Site` / `Delete Site` / `Import`（从工作区导入，只显示 Sig 文件）/ `Export` / `Save` / `New Signal` / `Delete Signal`（可多选批量删）。
**约束**：必须先 Add Site 才能 New Signal；空白参数位置会变红。

#### 3.4.1 资源共享（Share）

- 某 Signal 或某 Site 的资源暂时不用或已用完时，可**Share 给其他 Signal / Site**，提高资源利用率。
- **前提：硬件上必须支持，否则不能 share**。
- 被设为 Share 的两个 Signal **不可同时使用**（例：VDDA Share VDD 后，芯片同时需要 VDD 和 VDDA 供电就不可行，Test.cpp 中同时使用会报错）。
- Sig 中 Site0 设为 Share 后，**新增 Site 时该 Signal 默认也是 Share**。
- **只有 1 个 Signal 或 1 个 Site 时无法使用资源共享**。

#### 3.4.2 DIO 资源复用 TMU

- ST2500 内部 TMU 模块**通过 DIO 资源复用实现**；TMU 通道 0~3 默认对应 **DIO 0、1、16、17**，可同时使用。
- 默认可复用 4 个通道；**通过编程接口可将任意 DIO 复用为 TMU**，但此时**必须在 Sig 文件中把该通道定义为 TMU 信号**（P.109；对应 API 见 `tmu.SetupTmuOutputCh`）。

### 3.5 `.grp`（芯片引脚信号组文件）— 字段级

**作用**：将 Sig 中的 Signal 自定义分组，便于统一处理（P.113）。**一个信号组内信号类型必须全部相同**。

**结构**：`SigGroup`（信号组名）→ 包含若干 `SigName`（成员信号）。
**控件**：`New SigGroup`、`Delete SigGroup`、`AddSignal`（弹窗：先选 AFE 类型，再 Left 侧 SigName 中选中 → 点箭头加入右侧备选区 → OK；勾选 `Add/Remove all SigName` 可全加/全去）、`Import`、`Export`、`Save`。
**约束**：Select AFEtype 下拉**只列出 Sig 文件中已存在的 AFE 类型**。
**字段级语法（文本格式）：手册只给出 GUI 截图，未列出文本字段**。

### 3.6 `.tim`（Timing 管脚时序文件）— 字段级（重点）

**作用**：定义输入 Pattern 的**每一行 Vector 执行时间、各芯片管脚状态对应的 WFC 值与期望时间**（P.117）。**整个工程中 tim 文件只有一个**，但可在其中定义多个子 Timing。

| 字段 | 含义 |
|---|---|
| `Timing Name` | 新增的 Timing 名，**对应 Pattern 文件中的 WFT 列**；一个 Timing 对应一组波形序列 |
| `Period` | Pattern 中 Vector 的执行周期，**编辑时必须带单位**；最大允许 **256us** |
| `Signal` | 下拉选择芯片管脚（来自 Sig 文件）；支持以信号组方式操作多个信号 |
| `WFC` | 当前芯片管脚的状态索引值，手动编辑；Pattern 中通过该索引映射 Evt Event 状态 |
| `Evtn_Event` 0~3 | 当前 WFC 值对应的状态，下拉选择 |
| `Evtn_Expr` 0~3 | 当前状态变化的时间，**必须带单位** |

**Evt Event 状态值表（P.119 表 2-26）**

| 状态值 | 含义 |
|---|---|
| `D` | 低电平 |
| `U` | 高电平 |
| `H` | 期望输出高电平 |
| `L` | 期望输出低电平 |
| `X` | 不关注，任意状态都可以 |
| `Z` | 高阻态 |
| `P` | 保持状态 |
| `M` | 中间态 |
| `T` | **高压模式**（VHH 模式需在 Tim 中把指定管脚 WFC 设为 `T`；见 API `pinlevel.SetMode("VHH")`） |

**示例解读（P.120）**：`PassCodeTiming` 组，`Period = 1000ns`；BOOT0 管脚的 WFC `0` 对应 `D`（0ns 起低电平），WFC `1` 从 0ns 为低、500ns 变高。

**控件**：`Save`、`Expand`（展开所有 Timing 组）、`Load`（加载当前 tim 文件）、`UnLoad`、`Add Timing`；右键可"插入 WFC""插入 Signal""删除"。
**约束**：
- **编写 Pattern 时添加的芯片管脚，必须先在 Tim 文件中定义，否则编辑 Pattern 时报错**（P.120）。
- 周期应为 **4 的整数倍**（示例中 62.5ns 取为 64ns）（P.166）。
- 最大允许 Period **256us**（P.119）；API 侧 `UpdatePeriod` 最大 250us、最小 8ns（CHM `62_API_DIO_Timing`）。

### 3.7 `.pat`（Pattern 配置索引文件）— 字段级

**作用**：定义使用的 **Pattern 源文件索引名（Pattern Set Name）及其源文件路径**（P.121）。

| 字段 | 说明 |
|---|---|
| `Number` | PatternSet 编号，自动生成不可编辑 |
| `Pattern Set Name` | 手动编辑；**API 中 `dio.Pattern("<name>")` 的 name 即此处** |
| `Load`（复选框） | 勾选则选中当前行 Pattern |
| `Pattern Directory` | Pattern 文件路径，双击添加；**右键 → Open PatternTool 进入 Pattern 编辑** |
| `Comment` | 注释 |

**控件**：`Save`、`Load`、`UnLoad`、`Add Pattern`、`Delete Pattern`、`Selec All`、`Open PatternTool`。
**约束**：添加的 Pattern 文件保存在 **当前 Job 工程下的 `pattern` 文件夹**内，源文件为 **CSV 格式**；Path 中管脚状态值**必须与 Tim 文件中定义的一致**，否则 PatternTool 编辑会报错。

### 3.8 `pattern/*.csv`（Pattern 源文件）— 字段级

**表头字段（P.143 表 2-38）**

| 列 | 含义 |
|---|---|
| `Lable` | Label 标签，当前 Vector 的索引，双击编辑，**不可重复**，可为空 |
| `WFT` | 当前 Vector 对应的 Tim 文件中的 **Timing 组名**（必须是 Tim 中已存在的 TimingName） |
| `Sequence` | 执行微指令（见 4.10） |
| `Loops` | 图形化显示 Sequence 指令，**不可编辑** |
| `Comment` | 说明，可编辑 |

**其余列**：在 Loc/Sequence 后依次为各芯片**管脚信号列**，单元格内容为 **WFC 值**（即 Tim 中 WFC 列的索引），双击/右键选择。**所有值均在 timing 文件中定义**。

**Pattern 必须包含的信息**（P.167）：a) 芯片管脚名及其对应参考时钟；b) Pattern 中执行一行 Vector 所需时间（Period）；c) 每行 Vector 对应的电平信息（如 `0/1/X/Z/M/L/H`，可随意定义但必须在 Tim 中有对应说明）。

**约束**：Pattern 为 CSV 类型保存（Ctrl+S 同步保存到 csv 文件）；最后一行 Sequence 必须是 `stop`。

### 3.9 `.tmf`（测试项配置文件）— 字段级（重点）

**作用**：创建/编辑芯片测试项，并把测试项函数体写入 `Test.cpp`（P.123）。

**Tmf 级控件**

| 字段 | 含义 |
|---|---|
| `Save` | 保存对 Tmf 的编辑修改（**自动执行 Reload 命令**） |
| `New Test Function` | 新增一个测试项 |
| `SiteInitName` | Site 初始化函数名（不可编辑，与工位关联） |
| `SiteResetName` | Site 复位函数名（不可编辑，与工位关联） |
| `LoopCount` | 测试循环次数（可手动编辑） |
| `StopOnFail` | 勾选：循环测试中出现测试项失败就停止测试（例：LoopCount=100，第 10 颗失败即停，不再测剩余 90 颗） |
| `DoAll` | 勾选：测试项失败也继续运行当前回合后续测试项，**不执行分 BIN** |
| `SelectAllTest` | 勾选：所有测试项加入测试 |

**测试项表格字段（P.125 表 2-30）**

| 字段 | 含义 |
|---|---|
| `Number` | 测试项编号（自动生成） |
| `Test Function` | 函数名（自动生成，可下拉查看已存在函数；**不可重复**） |
| `Test`（勾选） | 将测试项函数加入测试；勾选变绿，取消变灰 |
| `Param ID` | 测试项编号（自动生成，不可编辑）。**子项 ParamID 从 0 开始**：第一个子项 1000→`ulParamID=0`，第二个 1001→`1` |
| `ParamName` | 测试项函数别名（可编辑）。API 中 `binObj.CheckResult(site, "PA4", ...)` 的字符串即此项 |
| `Min` / `Max` | 测试 Limit 上下限（可编辑） |
| `Unit` | 单位（可编辑） |
| `Sbin` | **软分档编号**，测试项结果在软件端的分 BIN 号 |
| `Hbin` | **硬分档编号**，测试结束后发给 Handler |
| `Results` | 下拉选择 `None / Pass / Fail` |
| `Comment` | 描述/注释 |

**特殊测试项**
- **`SetErrorBin`**：用于错误处理的测试项，**必须指定 Sbin 和 Hbin**。
- **`SetPassBin`**：芯片 Pass 的分 BIN 测试项，**只能有一个**，一般作为**最后一个测试项**；当前面所有测试项都没失败时才执行它。Sbin/Hbin 按实际情况定，其他参数不可编辑，`Results` 默认 `Pass`。

**Limit 的两种语义（P.126）**
1. **电参数比较**：测试结果落在 Limit 内即 Pass，按测试规范填上下限。
2. **输入 Pattern 比较**：Pattern 中已设比较，实际输出与预期一致即 Pass，**Limit 上下限一致，设为 `1`(True)**。

**Sbin / Hbin / Results 分 BIN 语义**
- `Results` 只能在**测试项**（父项）处编辑，**子项不可编辑**。
- `Results = PASS` → 当前测试项通过分到该 BIN；`FAIL` → 失败分到该 BIN；`NONE` → 不分 BIN。
- 例：测试项 A 的 `Results=Fail, Sbin=2, Hbin=3`，表示若芯片在 A 项失效（测试值在 Limit 之外），分 BIN 记录为 **2-3**；通过该记录可查失效项并知道落到 Handler 的 BIN3。

**编辑操作**：`New Test Function`、**`New Sub Test Group`**（按信号组批量建子项；可设 Cover/Before/After、Group、Prefix、Suffix、Min/Max）、`New Sub Test`（新增 N 个子项）、`Multi Edit`（多行同填）、`Remove`、`Up`、`Down`、`跳转`（跳到 Test.cpp 对应函数）、`Save`。
- 删除测试项函数后，**cpp 中对应函数体会被注释掉**。
