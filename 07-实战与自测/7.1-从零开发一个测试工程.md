## 二、逐个编辑工程文件

### 2.1 `.sig` —— 信号映射（课件 3，P.16–P.19）

```
① 双击资源视图下的 .sig，打开信号编辑界面
② 点击 Add Site / New Signal 分别添加 site 和 signal 编辑栏位
③ 编辑内容：
     SigName   —— 自定义输入（如 PA0、VDD）
     AFEType   —— 下拉选择（DPS / DIO / PPMU / TMU / CBIT / AWG / DGT / SMU …）
     ChType    —— 根据 AFEType 下拉设置（Inout / Supply / In / Out / Default / RxTx）
     通道      —— Adapter : FBID : Channel
```

**通道三元组定义（课件 3，P.19，权威口径）**：

```
                     X : X : X
                     │   │   │
第一个参数：定义当前需要使用的资源在哪个 Adapt 上（Parameter: 1-8）
第二个参数：定义在 Adapt 上哪块 Slot（Parameter: 1-5）
第三个参数：定义当下 Slot 中的具体哪个资源通道
```

**第三个参数的取值范围由"该资源在一块资源板卡上的数量"决定**（课件 3，P.19）：

| 资源 | 通道范围 |
|---|---|
| DPS | **0–3** |
| DIO | **0–31** |
| TMU | **0–3** |
| CBIT | **0–7** |
| AWG | **0** |
| DGT | **0** |

> ⚠️ **常见误解**：很多资料把 `1:1:0` 解释为"板卡:资源:通道"或"板卡:站点内资源:通道"。**权威定义是 Adapter（机头）: FBID/Slot（业务板）: Channel（通道）**，**不含"资源类型"层** —— 资源类型由 `AFEType` 字段单独指定。

### 2.2 `.grp` —— 信号分组（课件 3，P.20–P.22）

```
① 双击资源视图 .grp 文件，打开 grp 界面
② 点击 New GigGroup 来添加分组
③ 在 GrpName 对应栏位输入自定义命名
④ 双击 EditSignal 按钮，弹出窗口选择需要将哪些 Pin 添加为一个 Group
⑤ 选中需要分组定义的 SigName，点击箭头确定信号选择，按 OK 完成分组信号选择
   （点击反向箭头可以选中信号移除分组）
⑥ 完成后点击 Save，完成信号分组文件定义
```

**分组的价值**：代码里可以写 `ppmu.Signal(OUTPUT_PINS)` 而不是逐个写 14 个引脚。

### 2.3 `.tmf` —— 测试项定义（课件 3，P.23–P.31）

```
① 双击资源视图 .tmf（test Manage Flow）文件打开 tmf 编辑窗口
② 点击 New Test Function，新建一行作为测试项目编辑栏
③ 编辑完成内容后保存
```

**`Result` 列的三种取值**（课件 3，P.27）—— **会根据 limit 判断结果，共同决定测试是否继续往下执行**：

| Result 设置 | limit 判定 Fail | limit 判定 Pass |
|---|---|---|
| **fail** | **跳出分 Bin** | 继续执行下一个项目 |
| **pass** | 继续往下执行 | **进行分 Bin** |
| **None** | 无论 limit 判定 pass 或 fail，都**继续往下执行** | 同左 |

**添加 Sub Test（测量参数）的两种方法**：

| 方法 | 操作 |
|---|---|
| **方法一** | 在测试项目上右键 → "新建 Sub Test" → 根据当前测试项目中需要测量参数的数量设定增加的数量。**子测试项 Param ID 由系统生成**，按顺序增加；`ParamName` / `Min` / `Max` / `Unit` 可以编辑 |
| **方法二** | 根据 `.grp` 中已经定义的 **PinGroup 一次完成自动添加设置** |

**保存后自动生成函数框架（课件 3，P.31）**：
> tmf 的内容编辑完成后保存，**会在 test.cpp 里增加对应的测试函数**，便可以在每一个函数里编写对应测试项目的测试程序。

**两个特殊的系统项**：

| 项 | 作用 |
|---|---|
| **Set PassBin** | 当所有测试项目都测试 pass、顺序执行结束、中途没有 fail 被分到不良品 Bin，则会从最后一个项目顺序执行到 **Set PassBin**；此项目分 Bin 后判定为**良品，一般设置 Bin 参数为 1** |
| **Set ErrorBin** | 如果程序编写的测试逻辑或分 Bin 部分出现疏漏，无法顺利到设定的 fail Bin 或 pass Bin，则程序会运行到 **SetErrotBin** 并进行 Bin，此时需要**进行程序逻辑的确认**；此项目在**建立 tmf 开始自动生成**，只需要设置 Bin 参数并且**确保不要和正常测试项目相同** |

### 2.4 `Test.cpp` —— 测试程序主体（课件 3，P.32–P.35）

> - test.cpp 文件中编写的测试程序**控制测试资源施加测试条件对 DUT 进行测试**，并对测量结果进行运算处理，**是测试工程的核心部分**；
> - test.cpp 内部编写测试程序使用 **ST-IDE 提供的内置 API** 以实现对测试机硬件的操作，**另外支持标准的 C/C++ 程序**；
> - test.cpp 除用户自定义的测试项函数外，还**提供了一些系统预设的函数**供用户使用，这些函数**在特定的时机执行**，用户可根据需要在这些函数里添加代码。

**系统预设函数（执行时机）**：

| 位置 | 说明 |
|---|---|
| 头文件定义区域 | `#include` 与导出宏 |
| 全局变量 | **多工位控制使用** |
| ProjectReuse | 测试程序**重新加载**时使用 |
| ProjectInit | 测试程序**第一次加载**时执行 |
| ProjectReset | 测试程序**退出**时执行 |
| site_init | **每次测试开始**时执行 |
| site_reset | **每次测试结束**时执行 |
| EndOfWafer (EOW) | **CP 测试一片**测试结束时执行 |
| EndOfLot (EOL) | **FT & CP 测试 End Lot** 时执行 |
| `USER_CODE` 函数 | **用户定义的测试项，与 tmf 中建立的项目关联** |
| SetPassBin | 测试执行到这一个系统项目后**执行最终分 Bin** |

**API 参考手册（课件 3，P.36）**：
> 帮助文档中罗列了测试机不同资源的使用 API 以及规格讲解，并且**每个测试资源下都会有案例做参考**。

## 三、编译、加载、运行、看日志

### 3.1 编译（课件 3，P.37）

> 点击工具栏下的**编译工具**开始编译测试程序。

> ⚠️ **必须先 Build 再 Load**。手册明确：「此处新建 Project 文件后**必须先进行 Build 操作**，否则不能进行 Load 操作，直接 Load 会弹出错误提示**且 Project 项目会变红**。」

### 3.2 加载 Load（课件 3，P.38）

```
在资源视图里右键点击测试工程 → 在弹出的菜单点击 Load
→ Console 栏同步显示 Load 信息直到全部报 success
→ 没有红色字体报错说明 Load 成功，并且工具栏的图标变得可选
```

> **注意**：**一次只能 Load 一个 Project 项目**，如有已 Load 的项目，则无法对其它 Project 进行 Load。**不同测试工程之间切换建议重启软件。**

### 3.3 运行（课件 3，P.39–P.40）

```
① 打开 .tmf 文件，选中需要执行的测试项目
      LoopCount      —— 可以设置 loop 测试的次数
      DoAll          —— 测试在中途有 fail 发生，会继续往下执行测试
      SelectAllTest  —— 选中或释放所有 Test Function
② 点击菜单栏绿色 Run 按钮运行测试
   测试前先点小三角进入 Site Configuration，选择一次要运行的 site
```

### 3.4 查看 Log（课件 3，P.41–P.43）

```
在工具栏找到 Log 按钮，点击打开 Datalog 窗口
```

| 视图 | 说明 |
|---|---|
| **Table Log** | 以 **excel 表格方式**显示测试数据，**一个横行显示一次测试**，每列标识每个项目及项目下测量参数的结果 |
| **Text Log** | 以**测试项目分类**打印详细测试数据 |

### 3.5 其他常用快捷键（来自简明教程）

| 操作 | 快捷键 |
|---|---|
| 编译 | `Ctrl + B` |
| 加载 | `Ctrl + L` |
| 运行 | `Ctrl + R` |
| 卸载 | `Ctrl + U` |

## 四、完整流程速查卡

```
【准备】
  ① 开工控机 → 开测试机（指示灯变绿）→ 启动系统软件
  ② 登录（admin / dev / user，密码同用户名）
  ③ 选 Development 进入开发模式

【建工程】
  ④ File → New → Project，输入工程名（默认在 D:\MINI-ATE\workspace）

【配资源】（顺序建议：res → sig → grp → tim → pat → tmf）
  ⑤ .res ：点 Get Resources 获取机台自检到的板卡资源，确认 Online
  ⑥ .sig ：Add Site → New Signal，为每个 DUT 引脚指定 AFEType / ChType / Adapter:FBID:Channel
  ⑦ .grp ：把信号打包成 INPUT_PINS / OUTPUT_PINS / INOUT_PINS 等组
  ⑧ .tim ：定义 Wave Table（周期 + 各信号 WFC 的驱动/比较沿）
  ⑨ .pat ：登记 Pattern 名与向量 CSV 路径
  ⑩ .tmf ：New Test Function 逐项建立测试流；为每项加 Sub Test（ParamName / Min / Max / Unit）；
           设置每项 Fail 的 Sbin/Hbin 与 Result 列；确认 SetPassBin 与 SetErrorBin
  （保存 .tmf 后 Test.cpp 会自动生成对应的空函数框架）

【写代码】
  ⑪ 在 Test.cpp 的每个生成函数里按六步套路实现：
       变量定义 → 硬件选择 → 信号连接 → 参数设置 → 参数测量 → 复位
  ⑫ 用 binObj.CheckResultAndBin(site, results, count) 判限分 Bin
  ⑬ 在 SetPassBin 里执行 binObj.SetBin(1)

【跑起来】
  ⑭ Ctrl+B 编译（Build）→ 必须成功
  ⑮ Ctrl+L 加载（Load）→ Console 全 success，无红字
  ⑯ 打开 .tmf 选中测试项 → 设 LoopCount / DoAll → Site Configuration 选 site → Run
  ⑰ 点 Log 打开 Datalog → 看 Table Log / Text Log

【收尾】
  ⑱ Ctrl+U 卸载（Unload）；切换工程建议重启软件
```

## 五、写一个测试函数的"六步套路"（课件反复强调）

课件《10.课件-测试案例-电源管理芯片（TPS73625）》P.25 / P.30 把编写流程明确列为「**编程提示**」：

```
➪ 变量定义
➪ 硬件选择
➪ 信号连接
➪ 参数设置
➪ 参数测量
➪ 复位
```

对应的代码模板：

```cpp
USER_CODE void XXX_T(void)
{
    TEST_BEGIN
        // ① 变量定义
        ST_MEAS_RESULT result;

        // ② 硬件选择 + ③ 信号连接
        ppmu.Connect(...);

        // ④ 参数设置
        ppmu.Mode(FIMV);
        ppmu.CurrRange(...);
        ppmu.VoltClamp(2, -2);
        ppmu.Force(...);

        // ⑤ 参数测量
        result = ppmu.Measure(...);

        // ⑥ 复位
        ppmu.Reset();
        ppmu.DisConnect();

        // 判限分 Bin
        binObj.CheckResultAndBin(site, results, count);
    TEST_ERROR
        binObj.HandlerException(0);
    TEST_END
}
```

## 六、常见"卡住"的地方

| 现象 | 原因与解决 |
|---|---|
| Load 弹出错误、Project 变红 | **没有先 Build**。先 Ctrl+B 编译成功再 Load |
| 无法 Load 第二个工程 | **一次只能 Load 一个 Project**；切换工程建议**重启软件** |
| 工具栏图标灰色不可点 | 尚未 Load 成功（Load 后部分图标才会由灰变可选） |
| `.res` 里看不到资源 | 没点 **Get Resources**；或板卡实际不在位（OffLine） |
| 信号选不到想要的通道 | AFEType 选错，或该资源的 Channel 超出范围（DPS 0–3、DIO 0–31、CBIT 0–7、TMU 0–3） |
| `.tmf` 保存后 Test.cpp 没变化 | 需在 tmf 编辑器里点击保存（Save）；确认为当前工程 |
| 工程换机器后路径报错 | `.job` 的 `AteHomePath` / `jobDir`、`Makefile` 的 `RUNNER_HOME`、`.cproject` 的 include 路径都要改 |
| 测试结果全是 Fail 但看不出原因 | 打开 **Text Log**（按测试项目分类的详细数据）比 Table Log 更容易定位 |
